# Android Desk · 开源项目借鉴评估

> 版本：v1.0 · 核实时间 2026-11-12（Asia/Shanghai）  
> 性质：**调研记录**，不是需求文档。它回答「哪些开源项目值得对照、对照什么、不碰什么」。  
> 采纳的借鉴点已分别写进：[功能设计.md](./功能设计.md)（F1.10、§13）· [助手宿主架构.md](./助手宿主架构.md) §10 · [待实测清单.md](./待实测清单.md)（T2、T4、T7）· [开发方案.md](./开发方案.md)（§2 第 11 条、WP2、WP11、R1）。  
> 数据来源：GitHub API 与各仓库的说明、清单、构建脚本、文档。星标数、提交时间会变，以核实时间为准。本文不构成法律意见。

## 1. 结论

**没有可以整段合入的项目。做法是分头借鉴零件，而且零件几乎都在设计、行为和实测路径这一层，不在代码层。**

| 原因 | 性质 |
|---|---|
| 最接近的壳（Smart Dock、Yagni Launcher、MagicDesk）都是 GPL-3.0，而本仓库尚未选定许可证。拷入或改写它们的代码会带入 copyleft 义务 | 事实 |
| Apache-2.0 的三个各有硬伤：Lawnchair 是 7351 个文件的 Launcher3 分支；Taskbar 两年没有提交，核心靠反射调隐藏接口；Buddy 不是壳 | 事实 |
| 没有任何一个项目做了「HOME 壳里把助手当一等公民驻留，并由宿主强制确认闸门」。这部分只能自己写 | 判断 |

## 4. 逐项对照

### 4.1 [Smart Dock](https://github.com/axel358/smartdock)

面向平板和外接屏的桌面模式启动器。

| 维度 | 情况 |
|---|---|
| HOME 角色 | 声明 HOME 与 SECONDARY_HOME |
| 手机 / 平板外壳 | 有平板与桌面两种布局；底栏画成无障碍悬浮层，盖在所有应用之上 |
| 自由窗口 | 用 `ActivityOptions` 加启动位置、目标屏幕，反射调用 `setLaunchWindowingMode` 启动；调整已有窗口大小靠 root 执行 `am task resize`；读运行中任务靠 Shizuku |
| 助手驻留、确认闸门 | 无 |
| 无障碍 | 用于画底栏与拦截按键，不是给助手操控用 |
| 特权 | README 写明应装为系统应用，否则用 Shizuku；`WRITE_SECURE_SETTINGS` 需 adb 或 root；依赖隐藏接口绕过库；隐藏导航栏要 root、改 `build.prop` 或 LSPosed |

**借鉴（对照 API 路径，W0-T2）：** 它的启动参数组合就是 T2 要测的路径；它「启动靠公开加反射、摆放靠特权」的分工，印证了 [助手宿主架构.md](./助手宿主架构.md) §5 的三选一很可能落在「只能启动不能摆」。窗口预设（最大化、左右半屏、标准）可作窗口模式的交互参照。

**不合入：** 无障碍悬浮底栏（与「默认不叠系统悬浮层」相反）；隐藏接口绕过库与 `WRITE_SECURE_SETTINGS`、`QUERY_ALL_PACKAGES`、`MANAGE_USERS` 等权限；任何代码（GPL-3.0）。

### 4.2 [MagicDesk](https://github.com/mekhontsev/magicdesk)

安卓工作站：原生多窗口桌面、X11/Wayland、终端、Linux 容器、MCP 自动化。

| 维度 | 情况 |
|---|---|
| HOME 角色 | 启动受管桌面时临时拿走 HOME，关闭最后一个工作区后归还；启动时清理残留的 HOME 占用 |
| 手机日常桌面 | 无 |
| 桌面窗口 | Android 15+，经特权服务调用系统窗口管理；应用仍是真实的系统任务，不自绘标题栏 |
| 助手 / 自动化 | 可选的 MCP 服务与内置命令行；默认只给「观察」，控制、内容、输入、文件、命令、更新各自单独授权，每次调用都检查 |
| 特权 | 受管桌面必须有 Shizuku、兼容服务或 root；部分能力依赖厂商固件；设备初始化会写全局设置并可能要求重启 |

**借鉴（对齐设计，窗口模式里程碑与 M4）：**

- 能力如实上报的三条措辞：能力报告只说明前提，不代表授权；请求被接受不等于已就绪；读不到清单是错误，不是空列表。与重构决策 P6 一致。
- `docs/architecture-guardrails.md` 的窗口护栏，可在窗口模式设计评审时逐条对照。
- 自动化的分项授权模型。

**不合入：** 工作站范围；以特权服务为前提的架构；临时接管 HOME 的模型；带网络监听的自动化服务；任何代码（GPL-3.0-only）。

### 4.3 [Lawnchair](https://github.com/LawnchairLauncher/lawnchair)

基于 Launcher3 的开源桌面，当前分支对应 Android 16。

| 维度 | 情况 |
|---|---|
| HOME 角色 | 生产级 |
| 清单属性 | `singleTask`、`clearTaskOnLaunch`、`stateNotNeeded`、`resumeWhilePausing`、空 `taskAffinity`，与本项目一致。差异：输入法模式它用 `adjustPan`（本项目 `adjustResize`）；配置变化它多处理 `mcc|mnc`；它另声明 SECONDARY_HOME |
| 权限 | 声明了 `QUERY_ALL_PACKAGES`、`EXPAND_STATUS_BAR` 等 |
| 自由窗口、助手、确认闸门 | 无 |
| 特权 | 基本桌面功能不需要；最近任务集成需要 root |

**借鉴（对齐行为，M1 验收）：** 把它当作「默认桌面应该响应什么」的行为对照表，见 §5 第 3 条。

**不合入：** fork 或裁剪 Launcher3 代码树。与重构决策 §6、原生 Compose 栈都冲突。

### 4.4 [Yagni Launcher](https://github.com/T31n/YagniLauncher)

从零写的 Kotlin 加 Compose 桌面，技术栈与本项目 M1 最接近。

| 维度 | 情况 |
|---|---|
| HOME 角色 | 有；主 Activity 同样用透出壁纸的主题 |
| 架构 | 领域层纯 Kotlin；每个系统接口单独一个封装模块，藏在领域层接口后面 |
| 网格 | 移动、缩放、冲突解决在纯 Kotlin 模块里；约束测试 1134 行，另有移动、缩放测试与基准测试 |
| 规模 | 主屏功能约 2.8 万行，其中分页加拖放约 6000 行 |
| 系统请求 | 处理「添加快捷方式 / 小组件到主屏幕」（`CONFIRM_PIN_SHORTCUT`、`CONFIRM_PIN_APPWIDGET`）；声明 `ACCESS_HIDDEN_PROFILES`（私密空间） |
| 无障碍 | 有服务但不读取窗口内容 |
| 权限 | 声明了 `QUERY_ALL_PACKAGES`、`EXPAND_STATUS_BAR` |
| 自由窗口、助手、确认闸门 | 无 |

**借鉴（对照架构分层，M1 与 Phase 2）：** 网格算法「先测试后界面」的纪律；系统接口留接口缝；用它的规模校准拖放工作量；默认桌面应响应的系统请求。

**不合入：** 任何代码（GPL-3.0，且同栈最容易照着改写）；Hilt、Room、Proto DataStore 这套栈；`QUERY_ALL_PACKAGES`。

### 4.5 [Taskbar](https://github.com/farmerbb/Taskbar) 与 [libtaskbar](https://github.com/farmerbb/libtaskbar)

悬浮任务栏加开始菜单，支持自由窗口与 Android 10 外接屏桌面模式。

| 维度 | 情况 |
|---|---|
| 能力探测 | 系统特性 `FEATURE_FREEFORM_WINDOW_MANAGEMENT`，或全局设置 `enable_freeform_support`；Android 7.1 及以下另看 `force_resizable_activities` |
| 启动 | API 28 起反射 `setLaunchWindowingMode`，之前是 `setLaunchStackId`；另设启动位置与目标屏幕 |
| 版本断崖 | 代码对 Android 12 单独判为不支持（除非该屏幕默认自由窗口）；6.2 更新记录写明多数 Android 12 设备上经它启动自由窗口不可用 |
| 外接屏桌面模式 | SECONDARY_HOME 加全局设置 `force_desktop_mode_on_external_displays` |
| 特权 | 写上述设置需用 adb 授予 `WRITE_SECURE_SETTINGS`；反射需绕过隐藏接口限制 |
| libtaskbar 的代价 | 给宿主清单加上悬浮窗、使用情况访问、`QUERY_ALL_PACKAGES` |

**借鉴（对照 API 路径，W0-T2）：** 探测顺序与探针记录字段，见 §5 第 1 条。

**不合入：** libtaskbar 依赖（违反 [开发方案.md](./开发方案.md) 硬规则第 6 条）；旧系统的「隐形 Activity」技巧；要求用户用 adb 授权的设置流程。Apache-2.0 对复用的约束比 GPL 少，但不建议复用的原因是技术上的：停滞、反射、View 栈。

### 4.6 [Buddy](https://github.com/ghorbelhamdi/buddy-android)

悬浮气泡里的手机操控助手，在应用内的小型 Linux 里跑命令行智能体。

| 维度 | 情况 |
|---|---|
| 形态 | 浮在别人的桌面上，不是壳 |
| 操控 | 无障碍服务读屏、点按、输入、截屏 |
| 审批 | 由应用强制，不靠智能体自觉。按应用三档：信任（由智能体决定是否问）、硬（应用检查每次点按，遇发送、支付、删除类按钮必须先问）、智能（规则之外再由另一个模型复核） |
| 默认分级 | 消息、社交、邮件、通话、购物、金融类应用默认在「硬」档 |
| 敏感按钮识别 | 内置多语言词表，加用户自定的「总是问 / 不问」规则 |
| 自我保护 | 智能体不能点或输入 Buddy 自己的气泡、卡片、设置，因此无法替用户批准或放宽规则 |
| 确认形态 | 同意 / 修改 / 拒绝；另有多选一提问、在屏幕上标出需要用户自己做的位置 |
| 注入防护 | 屏幕文字与通知一律当内容，不当指令；由通知触发的任务权限更小 |
| 密码类 | 不代输密码、验证码、支付信息 |
| 特权 | 基本功能只需无障碍；后台模式靠无线调试开虚拟屏；README 说明 Google Play 因无障碍用途拒绝其上架 |

**借鉴（对齐设计，M5 的 ConfirmGate）：** 见 §5 第 2 条，已写入 [助手宿主架构.md](./助手宿主架构.md) §10.1。

**不合入：** 悬浮气泡作主界面；应用内置 Linux 与智能体命令行（等于内置助手，违反重构决策 §5）；联网、定位、录音、安装应用等权限；自更新；后台虚拟屏。

### 4.7 补充项目

**[DSH Go](https://github.com/ccch1mneyyy/dsh-Go)** 是要对齐的「驻留客人」，不是壳。

- 包名在其构建脚本里核实为 `io.github.ccch1mneyyy.dsh_app`。
- README 写明手机操控有三档确认，敏感操作默认交还用户；桌宠可开「App 外显示」跟到桌面；「不打扰模式」需 Android 14+ 加 Shizuku 或自连 ADB。
- 它有插件体系：插件是跑在引擎里的包，给出 JSON 视图，由应用用自己的组件画，样式有界。这与 [助手宿主架构.md](./助手宿主架构.md) §3.2「助手给结构化数据、由桌面渲染」是同一模式。
- **不引进任何源码，也不使用它的名称与吉祥物素材。** 概念可以对齐，规格自己写。

**[ClosePaw](https://github.com/imoonkey/closepaw)** 可与 ConfirmGate 对照的三点：银行、验证器、加密钱包类应用硬性封锁，任何设置都不能解除；陌生应用按「始终 / 本次 / 拒绝」逐个授权；标记了安全窗口的界面不交给智能体。另有动作可视化（点按画圈、滑动画线）。

**[Dextop](https://github.com/NarYuki/Dextop)** 只在评估 T3 兜底时参考它的机型表：三星 One UI 8 完整支持；Pixel 9a 部分可用；HyperOS 3.0 的 POCO X7 Pro 与 Android 13 的 Xperia 1 III 不可用。虚拟屏路线对厂商高度敏感，且需要特权运行时。

另外搜索过「原生桌面加助手驻留」类项目，没有找到比上述更接近且值得合入的。搜索不穷尽。
