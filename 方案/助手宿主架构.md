## 0. 要解决的问题

把「手机 AI 助手」从「贴在别人桌面上的悬浮窗」变成「这张桌面上的原住民」。分两件事，必须都做，不能只做显示：

1. **存在显示：** 桌宠、面板、助手窗口出现在桌面坐标系里，随分页、任务栏和窗口一起被管理。  
2. **操作桌面：** 助手能对这张桌面发出可审计的动作——打开应用、点图标、滑动抽屉、在支持时移动窗口、在其他应用里点按输入——并随时被用户停下。

---

## 1. 分层

```
┌─ 桌面壳（Compose）─────────────────────────────────────┐
│  壁纸与网格（本地面）                                   │
│  助手层（同一窗口里的桌宠/面板，不是另起一套系统悬浮层） │
│  系统窗口（仅在桌面窗口形态下，由 WM 摆放的应用窗口）    │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────┐
│  Host：Registry · SurfaceManager · ControlService        │
│         ConfirmGate · WindowCoordinator                  │
└─────────────┬──────────────────────────┬────────────────┘
              │ SDK（绑定服务）           │ Accessibility /
              ▼                           │ MediaProjection /
     协作助手（实现 SDK）                 │  Launcher / Freeform
     非协作助手（只当普通应用放上桌面）
```

协作助手的桌宠**画在桌面壳里**，这样它属于桌面，而不是再申请一层系统级悬浮窗。只有用户打开「离开桌面后仍显示桌宠」时，才允许改用系统悬浮窗跟随——默认关闭。

## 2. 表面类型

```kotlin
enum class SurfaceKind {
  PET,          // 桌宠：可拖动，不占网格
  PANEL,        // 对话/确认面板：可从桌宠或任务栏展开
  DESK_WINDOW,  // 把助手应用作为桌面上的窗口打开（需自由窗口能力）
  DOCK_ITEM     // 钉在底栏或任务栏
}

data class AgentBinding(
  val agentId: String,          // 白名单 id，如 "dsh-go"
  val packageName: String,      // 安装包名，不存运行时 token
  val surfaces: Set<SurfaceKind>,
  val matchStrategy: MatchStrategy = MatchStrategy.InstalledPackage,
  val cooperative: Boolean      // 是否实现了本 SDK
)
```

不把「某次运行的 windowId / sessionId」写成用户配置。应用升级或进程被杀后，应按包名重新贴上。

## 3. 非协作与协作

### 3.1 非协作（MVP 就要能用）

桌面只把对方当作已安装应用：

- 出现在抽屉里，可被放到桌面网格或底栏；
- 在桌面窗口形态下，可用自由窗口打开该应用；
- 不读取对方内部会话，不替换对方桌宠；
- 若对方自己的桌宠也开着，设置里提示「可能出现两只桌宠」，由用户关其中一侧。

这保证在 DSH Go 尚未接入 SDK 时，本桌面已经有价值：助手的「家」是这张桌子，启动路径变短。

### 3.2 协作（Phase 2）

助手实现 SDK，至少支持：

| 能力 | 说明 |
|---|---|
| 握手与能力声明 | 支持哪些表面、是否需要读屏/截屏、版本 |
| 桌宠状态 | `idle` / `thinking` / `acting` / `needsUser` / `stopped` |
| 面板内容 | 短对话、确认卡、进度，由助手提供结构化数据，**由桌面渲染**（避免再嵌对方 WebView） |
| 任务请求 | 向 Host 申请桌面动作，而不是自己去点 |
| 停止与暂停 | 遵守 Host 的全局停止 |

桌面负责摆放与渲染壳，助手负责智能与任务策略。这样确认闸门、停止按钮、权限说明只有一份。

## 4. 桌面操控面

### 4.1 动作原语（Host 唯一实现）

| 原语 | 作用对象 | 备注 |
|---|---|---|
| `launchApp` | 包名 / 桌面快捷方式 | 优先走 LauncherApps，不模拟去点图标（除非必要） |
| `openFolder` / `openDrawer` / `goToPage` | 本桌面 | 对桌面自己的状态机发命令，不走无障碍 |
| `moveWindow` / `resizeWindow` / `focusWindow` | 桌面窗口形态 | 仅当 W0 证实第三方能改窗口界 |
| `click` / `longPress` / `swipe` / `type` | 其他应用或桌面可见控件 | 无障碍手势或节点动作 |
| `readUiTree` / `takeScreenshot` | 当前任务 | 截屏需单独授权；树中的银行卡号/身份证号先打码再交给助手 |
| `stop` | 全局 | 立即取消进行中的动作序列 |

对本桌面内部的操作（翻页、开抽屉、启动已钉应用）应走**桌面 API**，不要用无障碍「点自己」，以免手势和动画不同步。

### 4.2 确认档位

与常见手机助手对齐，三档，默认最严：

| 档位 | 行为 |
|---|---|
| 每次都询问 | 进入新应用、发送、删除、付款前询问 |
| 本任务免确认 | 本任务问一次，其余步骤继续；发送/付款/删除仍每次问 |
| 始终免确认 | 须二次确认才能打开；建议仅临时使用 |

无论哪一档，密码、验证码、系统设置默认交还用户。解除这些限制要单独开关，并写明风险。

### 4.3 一键停止

桌面壳、通知（若已授权）、面板上始终能停。停止后：

- 进行中的手势立刻取消；
- 助手状态回到 `stopped`；
- 不自动恢复，必须由用户再发起。

息屏或锁屏时停止任务（与 DSH Go 的安全直觉对齐），避免在看不见的时候继续点。

## 5. 桌面窗口形态下的窗口策略

目标：在支持的设备上，应用窗口与助手共处桌面。

| 能力 | 依赖 | 未知项 |
|---|---|---|
| 以自由窗口启动一个 Activity | `WindowConfiguration` / `ActivityOptions.setLaunchWindowingMode` 等，且系统开启 freeform | 第三方启动器是否被允许设置 windowing mode，见 W0-T2 |
| 移动、缩放已存在的任务 | 系统 Desktop Windowing / 隐藏 API / 无 | 很多接口是系统应用或签名权限，W0 必须给出「能做 / 只能启动不能摆 / 完全不能」三选一 |
| 虚拟屏合成（自行画窗口） | MediaProjection + VirtualDisplay | 能绕过 OEM 限制，但代价是输入转发与性能；仅当系统自由窗口不可用且 W0-T3 证明可行时，作为后期备选，不作为 MVP 承诺 |

**硬约束：** MVP 不得把「自绘远程桌面式窗口」写成已交付能力。先用系统能力，不够再评估虚拟屏。

活跃窗口策略：低内存或手机启动器形态下，不以多窗口为默认。平板且系统支持时，允许若干并排窗口；具体上限 W0 回填。

## 6. 与 DSH Go 的具体关系

DSH Go 已具备：本机引擎、桌宠、手机操控（无障碍）、确认档位、插件体系。本桌面不复制这些能力，只提供更好的「家」。

| 阶段 | 做法 |
|---|---|
| 非协作 | 识别其安装包，提供「放到桌面 / 钉到任务栏 / 在窗口中打开」；不关闭对方自己的桌宠，只提示冲突 |
| 协作（需对方或社区插件） | DSH Go 通过 SDK 把桌宠和确认卡交给本桌面渲染；手机操控尽量改走本桌面的 ControlService，避免两套无障碍同时下手 |

在对方尚未提供插件前，本仓库只做 SDK 与 sample-agent，不修改、不分发 DSH Go。

DeepDeep 按同样的两阶段模型预留。未核实包名之前，不得在代码里写死匹配规则。

## 7. SDK 形状（草案，M4 定稿）

稳定面拟用绑定服务 + AIDL（或等价的官方 IPC），而不是让助手 `startActivity` 进我们的私有组件。握手流程：

1. 桌面按白名单或用户「允许驻留」列表查找实现了约定 Intent 的服务；  
2. 双方交换版本与能力；  
3. 桌面授予本次会话 token（仅本机，短时有效）；  
4. 助手上报表面与状态，申请动作；  
5. 用户撤销授权或卸载后，会话作废。

SDK 不得要求助手持有无障碍权限才能驻留显示。显示与操控解耦：只当桌宠可以不授予读屏。

## 8. 失败与空态

| 状态 | 桌面怎么做 |
|---|---|
| 助手未安装 | 绑定页保留，显示「未安装」，提供应用来源说明（不擅自外链下载未经确认的包） |
| 助手已安装但未授权驻留 | 当作普通应用图标，不进入桌宠层 |
| SDK 版本不兼容 | 降级为非协作，并说明「当前仅能作为应用打开」 |
| 无障碍未开 | 桌宠可在，操作按钮引导去开启 |
| 自由窗口不可用 | 打开助手走普通全屏 Activity；设置中写明原因 |
| 操控任务进行中离开桌面 | 启动器形态下任务可按设置继续或暂停；默认：若桌宠未跟随，则暂停并通知用户 |

## 9. 分期

| 里程碑 | 宿主能力 |
|---|---|
| M1–M3 | 桌面可用。尚无助手舞台也可验收桌面本身 |
| M4 | SurfaceManager + 样例助手桌宠/面板；绑定按包名 |
| M5 | ControlService + ConfirmGate + 停止；仅样例助手走完整协作 |
| M6 | DSH Go 非协作放置；在 W0 通过的设备上尝试窗口打开 |
| 之后 | 正式协作适配、虚拟屏备选方案（仅当 T3 正向且有明确需要） |
