## 0. 目标架构

```
┌─────────────────────────────────────────────────────────────┐
│  Android Desk Shell（Jetpack Compose）                       │
│  桌面画布：壁纸 · 网格图标 · 分页 · 文件夹 · 小组件          │
│  壳层：底栏 / 任务栏 · 应用抽屉 · 搜索 · 整理模式            │
│  助手层：桌宠舞台 · 面板槽 · 桌面窗口（系统支持时）          │
│  声明：HOME / DEFAULT，可被设为默认主屏幕                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ 进程内（MVP 同进程）
┌──────────────────────────▼──────────────────────────────────┐
│  Android Desk Host                                          │
│  ├ DesktopLayoutStore   页、图标、底栏、网格的本机权威数据   │
│  ├ LauncherCatalog      已安装应用、快捷方式、卸载监听       │
│  ├ WidgetHost           AppWidget 宿主（Phase 2）            │
│  ├ AgentRegistry        白名单发现、能力协商、绑定           │
│  ├ SurfaceManager       桌宠 / 面板 / 窗口表面生命周期       │
│  ├ WindowCoordinator    自由窗口 / Desktop Windowing 适配    │
│  ├ ControlService       读屏、手势、输入（无障碍等）         │
│  ├ ConfirmGate          确认档位、敏感操作、一键停止         │
│  └ PermissionState      权限与降级，不伪造「已是桌面」       │
└─────────────┬────────────────────────────┬──────────────────┘
              │ Agent SDK（AIDL / 绑定服务） │ 系统 API
              ▼                              ▼
┌──────────────────────────┐    ┌────────────────────────────────┐
│ 已安装助手               │    │ ROLE_HOME · LauncherApps        │
│ DSH Go / DeepDeep /      │    │ Wallpaper · AppWidget           │
│ sample-agent             │    │ Accessibility · MediaProjection │
└──────────────────────────┘    │ Freeform / Desktop Windowing    │
                                └────────────────────────────────┘
```

没有 Mac Host，没有局域网投屏主路径。发现、布局、助手绑定的权威数据都在本机。

## 1. 工程结构（目标）

```
AndroidDesk/
  app/                 # 桌面 APK：HOME Activity、引导、设置
  core/                # 纯 Kotlin：模型、布局、确认闸门、协议（可 JVM 单测）
  host/                # 宿主逻辑：注册、匹配、权限状态机（平台实现等 W0）
  client/              # 壳层逻辑：手势与页状态、预览/默认桌面映射
  sdk/                 # 给第三方助手的稳定 API（AIDL + 客户端库）
  sample-agent/        # 样例助手 APK，只为验证 SDK
  w0probe/             # W0 实测工具（不进产品 APK）
```

**边界（硬规则）：**

- `core` 不得引用 Android 框架。布局算法、确认闸门、绑定匹配必须可单测。
- `sdk` 是对第三方的稳定面，破坏性变更要升版本；App 不得让第三方直接绑内部类。
- 读屏、注入、截屏、自由窗口启动**只实现一份**，放 `host`。桌面壳与样例助手都走同一套接口，禁止再写一条「本机直通」。
- `w0probe` 不打进产品 bundle。

## 2. 进程形态

| 阶段 | 形态 | 理由 |
|---|---|---|
| M1–M3 | 桌面壳与 Host **同进程** | 作为 Launcher 被系统保活的是这一个进程；权限只授予一个包名 |
| M4 起评估 | 操控（无障碍）仍在本应用内的 AccessibilityService；是否把编码/虚拟屏放到独立进程，按 W0 稳定性决定 | 无障碍服务崩溃不应只靠「不会崩」来假设 |

无障碍服务必须属于本应用包。第三方助手在协作模式下**不再各自抢第二套桌面操控无障碍**（它们原有的应用内能力不受本规则禁止，但桌面要能提示冲突）。

## 3. 作为主屏幕的系统集成

### 3.1 要声明的角色

- `AndroidManifest` 中桌面 Activity 带 `android.intent.action.MAIN` + `android.intent.category.HOME` + `android.intent.category.DEFAULT`
- Android 10+ 使用 `RoleManager.ROLE_HOME` 发起「设为默认主屏幕」
- 同时保留普通 `LAUNCHER` 入口，便于未设默认时从应用列表打开预览

### 3.2 桌面必须响应的系统事件

| 事件 | 行为 |
|---|---|
| 应用安装 / 卸载 / 更换图标 | 更新抽屉与桌面上对应图标；卸载后去掉桌面占位，不留死图标（可保留「已卸载」短时空态后清除） |
| 用户按 Home | 已是默认桌面时回到第 1 桌面页或记录的默认页；关闭抽屉与整理模式 |
| 配置变化（旋转、折叠、分屏） | 按宽度选择底栏或任务栏；网格列数重算，图标位置按格子保存而不是按像素保存 |
| 壁纸变化 | 使用系统 WallpaperManager，尊重实时壁纸 |

### 3.3 布局数据权威

桌面页、图标位置、底栏/任务栏钉住的应用、助手绑定，一律存在本机（DataStore / 文件），由 Host 读写。壳层不另存一套会打架的布局。

格子坐标用 `(pageIndex, cellX, cellY, spanX, spanY)`，这样换机或改列数时可以再排，而不把像素写死。

## 4. 权限与降级

| 权限 / 角色 | 用于 | 缺失时 |
|---|---|---|
| `ROLE_HOME`（用户选择） | 成为默认主屏幕 | 预览模式；桌面能用，但按 Home 回不到这里 |
| 查询已安装应用（可见性） | 抽屉、放图标 | 只列出系统允许可见的应用，并说明「部分应用因系统限制未显示」 |
| 无障碍 | 助手操作桌面与应用 | 桌面本身可用；助手舞台可显示，但操控入口关闭并给出引导 |
| 悬浮窗（可选） | 桌宠在离开主屏幕后跟随 | 桌宠仅出现在本桌面上（这是默认，也是推荐） |
| MediaProjection / 截屏（可选） | 给需要看图的助手提供屏幕帧 | 仅提供无障碍树；不因此阻塞桌面 |
| 通知（可选） | 确认卡、停止按钮 | 改用桌面上的确认条 |
| Shizuku / ADB（可选，后期） | 部分 OEM 上的增强操控 | 不作为 MVP 依赖 |

权限失败返回明确状态，禁止用空桌面或假图标冒充「没有应用」。

## 5. 安全

1. 本桌面默认不采集、不上报使用数据。  
2. 助手白名单：未登记且未获用户「允许驻留」的应用，不能写入桌宠层，也不能调用操控 API。  
3. 确认闸门只在 Host 实现一份，SDK 客户端改不掉档位。  
4. 密码、验证码、支付、系统设置页默认拒绝代操作。  
5. 截屏与无障碍树只交给当前被用户允许的那一个任务，任务结束即停。  
6. 不在日志里写下键盘内容与屏幕全文。

---

## 6. 性能与保活

- 启动器进程会被频繁唤醒：冷启动到第一帧桌面要短，图标与壁纸可分阶段呈现（先网格后图标）。
- 不做常驻前台通知来「保活桌面」——它应当靠 HOME 角色被系统对待。
- 桌宠动画在息屏与本桌面不可见时必须停止。
- 桌面窗口形态下，同时打开的窗口数与动画档位可配；低内存设备默认启动器形态。

## 7. 演进

1. 先成为一张能日常使用的原生桌面，再放助手。助手权限绝不能挡住「当桌面用」。  
2. 先非协作放置，再协作 SDK。  
3. 先启动器形态，再在实测支持的设备上打开窗口形态。  
4. 未通过 W0 阻塞项的平台能力，代码里只留骨架。
