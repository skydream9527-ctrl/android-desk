# Android Desk · 任务提示词

> 版本：v1.0 · 2026-11-12（Asia/Shanghai）  
> 用途：把 [开发方案.md](./开发方案.md) 的每个工作包交给一个 agent 时，直接复制对应的一段。  
> 每段都是自包含的：agent 不需要看过别的对话，照着读文档、改文件、验收、汇报即可。

---

## 怎么用

1. **基线在 `m1-baseline` 分支。** 建议先把它合并到 `main`，然后所有 agent 都从 `main` 切分支。下面的提示词里写的是「从基线分支切出」，两种情况都适用。
2. 按下表的顺序派发。同一行里的可以同时派给不同的 agent。
3. **并行的 agent 必须各用各的工作目录**（各自的 git worktree 或各自的克隆），否则会互相覆盖文件。
4. 每个 agent 交回后，先看它的汇报里「在什么设备上验证了什么」。没有实机验证的不算完成。
5. 一个工作包合并后，再派发依赖它的下一个。

| 轮次 | 可同时派发 | 前提 |
|---|---|---|
| 1 | WP0 环境 · WP8 助手管线 | 基线已在分支上 |
| 2 | WP1 入口与根界面 | WP0 完成 |
| 3 | WP2 桌面画布 · WP4 应用面板 · WP6 图标样式 · WP9 助手层界面 | WP1 已合并（WP9 另需 WP8 已合并） |
| 4 | WP3 抽屉 · WP5 应用管理 · WP7 设置 · WP10 样例助手 | 分别在 WP2 / WP4 / WP6 / WP8 之后 |
| 5 | WP11 的各子项（可拆给多个 agent） | 全部 P0 工作包已合并并验收 |
| 6 | WP12 测试、实测与验收 | 其余全部完成 |

**关于设备：** 界面类工作包（WP1–WP7、WP9、WP10、WP12）要求在模拟器或真机上验证。如果派发的 agent 所在环境没有可用设备，它只能交出「已编译，未实机验证」的结果，需要你或另一个有设备的 agent 补验收。WP8 是纯逻辑加单测，大部分不需要设备。

```text
你要为 Android Desk 项目准备好构建与实机验证环境。这是后面所有界面开发的前提：
现有的应用代码能编译，但从来没有在任何设备上运行过，原因就是这台机器上没有模拟器。

项目：Android Desk 是一张安卓原生桌面（Launcher）。仓库里 `AndroidDesk/` 是代码，`方案/` 是设计文档。

先读：
1. AndroidDesk/BUILD.md
2. 方案/开发方案.md 的 §1.1 和 §8 里的「WP0 基线与环境」

要做的事：

哪一步没做成以及原因。只改了 BUILD.md 的话，提交到从基线分支切出的 `wp0-env` 分支。
```

## WP1 入口与根界面骨架

```text
你要让 Android Desk 第一次真正跑起来：装上能打开，能设为默认主屏幕，并为其余界面
搭好可以并行填充的骨架。这是整个项目的关键一步——后面四条开发线都等着它。

项目：Android Desk 是一张安卓原生桌面（Launcher），用 Kotlin + Jetpack Compose。
仓库里 `AndroidDesk/` 是代码，`方案/` 是设计文档。

现状：状态控制器、应用目录、图标渲染、桌面画布都已经写好并能编译，但入口
`LauncherActivity.kt` 还是一个空的占位类，所以现在打出的 APK 启动即崩。
已写的代码从未在设备上运行过，你是第一个运行它的人，遇到已写代码里的问题是正常的。

先读（按顺序）：
1. 方案/重构决策.md —— 产品是什么、明确不做什么
2. 方案/开发方案.md 的 §0–§7 全部，以及 §8 里的「WP1 入口与根界面骨架」
3. 方案/功能设计.md 的 F1.1、F1.8、F2.3
4. 方案/页面设计.md 的 §0（跳转关系）、§1.2（层级）、§1.3（安全区）
5. 已有代码：app 模块下的 DeskController.kt、DeskGraph.kt、ui/Desktop.kt、ui/DeskHost.kt、
   home/SystemHome.kt

负责文件：
- LauncherActivity.kt（重写）
- ui/DeskRoot.kt（新建）
- 以下文件的占位版（新建，签名必须与开发方案 WP1 第 4 步完全一致）：
  ui/AppDrawer.kt、ui/AppSheet.kt、ui/DeskMenuSheet.kt、ui/AppManagerScreen.kt、
  ui/IconStyleScreen.kt、ui/StylePickers.kt、ui/SettingsScreen.kt、ui/AgentLayer.kt
- DeskController.kt：只新增 `managerFilter` 字段与 `openAppManager(filter)` 方法

要做的事，按开发方案 WP1 的四步来。几个容易出错的地方：
- Activity 的全部系统集成细节在开发方案 §7.1 的表里，逐行实现，不要凭记忆写。
- 判断「设为默认」是否成功时不要看 resultCode，回调里重新查询系统。
- S1 桌面画布和 S2 抽屉的根容器不能画不透明背景，否则壁纸透不出来。
- 占位界面只需显示页面名和一个返回按钮。它们的函数签名是别的 agent 并行开发的契约，
  一个参数都不要改。
- 「回到系统桌面」的分支逻辑（0 个 / 1 个 / 多个且记住 / 多个未记住）写在 DeskRoot 里，
  供桌面菜单和设置共用。

验收（在手机模拟器上逐条做）：
1. 安装后能打开，看到壁纸、预置图标、底栏、顶部的预览横条。
2. 点「设为默认」出现系统弹窗；确认后横条消失，按 Home 回到本桌面。
3. 重新安装或清除默认后再试一次，这次在系统弹窗里取消：出现提示
   「还没有改过来。你可以随时在桌面设置里再试。」且横条仍在。
4. 画布上按返回：已是默认时无反应；预览模式下退出。
5. 已在桌面时按 Home 回到第 1 页。
6. 杀掉进程后重开，布局仍在。
7. `./gradlew testAll :app:assembleDebug :app:lintDebug` 全部通过，lint 为 0 error。

约束：遵守开发方案 §2 的十条硬规则；界面文案只用 页面设计.md §14 文案表里的；
不新增权限、不联网、不新增第三方依赖。发现已写代码有问题可以修，但要在汇报里逐条列出。

完成后汇报：改了和新建了哪些文件；在什么设备、什么系统版本上做了上面哪几条验收、
每条的结果；修了已写代码里的哪些问题；哪些没验证及原因。
没有在设备上跑过的内容写「已编译，未实机验证」，不要写「已完成」。
提交到从基线分支切出的 `wp1-entry-root` 分支，并更新 开发方案.md §1.2 的状态记号。
```

```text
约束：遵守开发方案 §2 的硬规则；位置永远存格子不存像素；不要为了省事改动

完成后汇报：发现并修正了哪些偏差（现象、原因、改法）；每条验收在什么设备上的结果；
```

## WP5 应用管理页

```text
你要实现 Android Desk 的应用管理页：一页列出手机里全部已安装应用，以及每个应用在
桌面上的状态，用户在这里把应用添加到桌面或拿走。「桌面上放什么由用户挑」是这个
产品的基本设定，这一页是挑的主要场所。

项目：Android Desk 是一张安卓原生桌面（Launcher），用 Kotlin + Jetpack Compose。
仓库里 `AndroidDesk/` 是代码，`方案/` 是设计文档。

先读（按顺序）：
1. 方案/重构决策.md
2. 方案/开发方案.md 的 §0–§7，以及 §8 里的「WP5 应用管理页」
3. 方案/功能设计.md 的 F3.2、F4.1（多选 F4.3 和排序 F4.4 这次不做）
4. 方案/页面设计.md 的 §7.1（S5 默认态）、§14 文案表
5. app 模块的 DeskController.kt 里的 DeskUiState 及其查询方法

负责文件：ui/AppManagerScreen.kt（目前是占位，签名不要改）。

要点：
- 初始筛选取 state.managerFilter（从桌面菜单「添加应用」进来时是「未添加」）。
- 四个筛选后面的数量，按「搜索之后的结果」计算，并且要自洽：桌面上 + 未添加 = 全部。
- 状态行由片段拼成，顺序固定：桌面第 N 页 → 底栏 → 已隐藏 → 已允许操作桌面；
  一个都没有时显示「未添加」。
- 行尾按钮：未在桌面是实心「添加」，已在桌面是描边「移除」。
  「移除」只拿走桌面页上的图标，不影响底栏。
- 点行的其余区域调 onOpenAppSheet。
- 行尾按钮的无障碍名称要带应用名（如「把 微信 添加到桌面」）。
- 列表用 LazyColumn，key 用 entry.key。

验收（手机模拟器）：
- 四个筛选的数量自洽；输入搜索词后数量随之变化。
- 从桌面菜单点「添加应用」进来，筛选停在「未添加」。
- 在「未添加」下点「添加」：出现提示「『〈名称〉』已放到桌面第 N 页」，
  该行从列表消失，汇总数字变化；回到桌面能看到图标。
- 在应用面板里切任何开关，列表的状态行立即变化。
- `./gradlew testAll :app:assembleDebug :app:lintDebug` 通过。
```
