本轮范围由两部分合成：

1. 既有方案（PRD v1.0）中的 **M1 桌面本体**。

## 2. 角色与核心场景

| 角色 | 是谁 | 在这张桌面上能做什么 |
|---|---|---|
| 用户 | 手机 / 平板的主人 | 一切。也是唯一能授权、改确认档位、停止助手的人 |
| 助手 | 用户另外安装的 AI 助手应用（如 DSH Go），或调试用的 ADB | 只能做 F6.2 列出的桌面动作，且受授权、确认、停止约束 |
| 桌面 | 本产品 | 执行动作、把助手在做的事展示给用户、守住闸门 |

**本桌面不内置大模型，也不联网。**「AI」来自用户安装的助手应用；桌面提供的是舞台和一套受控的操作入口。

### 场景 S-A：第一次用

1. 安装后从应用列表点开，看到真实桌面：系统壁纸、底栏里有电话 / 短信 / 浏览器 / 相机（设备上有的才出现），第一页有设置等几个系统应用。
2. 顶部横条写着「预览模式 · 尚未设为默认主屏幕」，右侧按钮「设为默认」。
3. 点按钮，在系统弹窗里选 Android Desk。横条消失。此后按 Home 回到这里。

### 场景 S-B：把手机里的应用摆上来

1. 长按桌面空白 → 桌面菜单 → 「添加应用」。
2. 进入应用管理页，筛选自动停在「未添加」。
3. 逐个点「添加」，或搜索名称后添加；每点一次，Toast 提示放到了第几页。
4. 返回桌面，新图标按阅读顺序排在第一个空位。

### 场景 S-C：换一套图标样子

1. 桌面菜单 → 「图标样式」。
2. 顶部预览区实时显示当前桌面上的几个应用。点「六边形」、点「玻璃」，预览立刻变。
3. 返回桌面，全部图标已换。
4. 觉得微信的图标在玻璃风格下不好认：长按微信 → 应用面板 → 图标样式 → 单独改回「原生」。

### 场景 S-D：和助手一起整理桌面

1. 用户在「设置 › 助手与操控」里把某助手打开。桌面上出现桌宠。
2. 用户对助手说「把常用的办公应用放到第二页」。
3. 助手先读取桌面布局和应用列表（不弹确认）。
4. 助手请求「把『飞书』放到桌面第 2 页」。桌面弹出确认卡：「〈助手名〉想要：把『飞书』放到桌面」，按钮「允许这次」「不允许」。
5. 用户点「允许这次」。桌面自动翻到第 2 页，飞书图标出现并被蓝圈高亮约 2 秒；状态条显示「已把『飞书』放到桌面第 2 页」。
6. 与此同时用户自己可以继续拖别的图标——两边改的是同一份桌面。
7. 用户觉得够了，点「停止」。助手后续请求全部被拒，直到用户点「继续」。

### 场景 S-E：回到原来的桌面

1. 桌面菜单 → 「回到系统桌面」。
2. 设备上只有一个别的桌面：直接切过去。有多个：弹出选择框，选一个，并记住。
3. 想彻底换回去：设置 → 「更换默认桌面」→ 跳到系统设置页，由用户改。

## 3. F1 桌面本体

### F1.1 默认主屏幕与预览模式（P0）

| 项 | 规则 |
|---|---|
| 声明 | 桌面 Activity 声明 `MAIN + HOME + DEFAULT`，另保留 `MAIN + LAUNCHER` 作预览入口 |
| 判定是否默认 | Android 10+ 用 `RoleManager.isRoleHeld(ROLE_HOME)`；更低版本用解析 HOME Intent 的默认处理者。**只认系统的答案，不自己猜** |
| 何时刷新判定 | 每次桌面回到前台、系统选择器返回后 |
| 预览模式 | 未成为默认时：顶部常驻横条 + 「设为默认」按钮；桌面功能完整可用 |
| 发起设为默认 | Android 10+ 调起系统的角色请求弹窗；更低版本或角色不可用时跳系统「默认主屏幕」设置页 |
| 用户取消 | Toast：「还没有改过来。你可以随时在桌面设置里再试。」横条保留 |
| 成为默认后 | 横条消失；设置页对应行改为「已是默认主屏幕」，不再显示设为默认按钮 |

**验收：** 预览和默认两种状态下，横条的有无与设置页文案都正确；取消系统弹窗不会被当成已设置。

### F1.2 桌面页与网格（P0）

| 项 | 规则 |
|---|---|
| 分页 | 横向分页，跟手滑动，松手吸附。页数 1–N，由内容决定（见 F1.5） |
| 网格 | 每页 `列 × 行` 个格子。位置以 `(页, 列, 行)` 保存，**不存像素** |
| 网格大小 | 由屏幕**短边与长边**和密度档位算出（见 F1.9），横竖屏用同一套网格，旋转不打乱图标 |
| 图标 | 一个应用入口在桌面页上最多一个图标。点按打开；长按拾起（F1.5） |
| 名称 | 图标下方一行，超长省略；可在图标样式里整体关闭 |
| 页指示器 | 页数 > 1 时显示圆点；点某个点直接跳到该页 |
| 手机方向 | 短边 < 600dp 的设备锁定竖屏 |
| 平板方向 | 短边 ≥ 600dp 跟随系统旋转，网格不变，格子长宽比变化 |

**边界：**

- 保存的布局里出现已不存在的应用：加载应用列表后自动清掉，不留死图标。
- 应用列表还没加载完时**不做清理**（避免把「还没读到」误判成「全卸载了」）。
- 屏幕尺寸变了（折叠屏开合、改密度）：仍放得下的图标原地不动，放不下的按阅读顺序从它原来那页往后找空位，不够就加页。

**验收：** 4×6 网格下放满 24 个再加第 25 个，自动出现第 2 页；旋转平板后每个图标仍在原来的格子；杀进程重开布局不变。

### F1.3 底栏 / 任务栏（P0）

| 项 | 手机（宽 < 600dp） | 平板（宽 ≥ 600dp） |
|---|---|---|
| 形态 | 底部通栏圆角条 | 底部居中圆角条，最大宽 640dp |
| 槽位数 | 4 个应用 + 1 个「全部应用」按钮 | 6 个应用 + 1 个「全部应用」按钮 |
| 图标 | 不显示名称；样式跟随图标样式设置 | 同左 |
| 点按 | 打开应用 | 同左 |
| 长按 | 打开应用面板（可从底栏拿走） | 同左 |
| 放入方式 | 把桌面图标拖到底栏；或应用面板里「钉在底栏」 | 同左 |
| 已满 | Toast：「底栏已满，先拿走一个再钉」 | 同左 |

- 底栏里的应用与桌面页上的图标**互相独立**：从桌面页移除不影响底栏，反之亦然。
- 底栏位置以槽位序号保存；槽位数变少时保留靠前的。
- 平板任务栏**不显示「正在运行的应用」**：第三方桌面拿不到完整最近任务，不做假的（重构决策 P6）。
- P1：底栏内拖动换序。

**验收：** 把桌面图标拖进底栏后两处都有；卸载该应用后两处同时消失。

### F1.4 应用抽屉与搜索（P0）

| 项 | 规则 |
|---|---|
| 打开 | 桌面上任意位置上滑（超过 56dp）；或点底栏最右的「全部应用」按钮；或助手请求 |
| 内容 | 全部可启动应用，按名称排序（中文按拼音序），**不含**用户隐藏的应用，不含本桌面自己 |
| 搜索 | 顶部搜索框。匹配应用名或包名，不区分大小写，包含即命中。P1：拼音首字母 |
| 点按 | 打开应用，抽屉保持（按 Home 回来时关闭） |
| 长按 | 打开应用面板（放到桌面、钉到底栏、隐藏、改图标、应用信息、卸载） |
| 关闭 | 返回键 / 返回手势；点右上角关闭；在顶部搜索区下滑 |
| 入口 | 右上角「管理」进入应用管理页 |
| 空结果 | 「没有找到『〈关键词〉』」 |

**验收：** 输入包名片段能找到应用；隐藏的应用不出现在抽屉但仍在应用管理里。

### F1.5 整理（P0）

没有单独的「整理模式」开关——长按图标就是整理。

| 动作 | 结果 |
|---|---|
| 长按图标（约 400ms） | 震动一下，图标被拾起（原位变空，手指处出现放大 1.12 倍的图标） |
| 拾起后没移动就松手 | 打开该应用的应用面板 |
| 拖到空格子松手 | 移到该格 |
| 拖到有图标的格子松手 | 两者换位 |
| 拖到底栏松手 | 钉到底栏第一个空槽（桌面页上的图标保留）；满了给提示 |
| 拖到顶部「拖到这里，从桌面拿走」条松手 | 从桌面页移除（不卸载；底栏里的不受影响） |
| 拖到屏幕左 / 右边缘停留 0.6 秒 | 翻到上 / 下一页，图标跟着走 |
| 在最后一页右边缘停留，且最后一页还有别的图标 | 新增一页并翻过去 |
| 松手后 | 末尾的空页自动收掉（至少保留 1 页） |

拖动过程中：目标格子显示浅色高亮框；移到「拿走」条上方时该条变红并改字为「松手，从桌面拿走」；分页的手动滑动暂时禁用。

长按**空白处**：打开桌面菜单（添加应用、应用管理、图标样式、壁纸、桌面设置、回到系统桌面）。

**验收：** 上表每一行逐条可复现；拖动中抬手在屏幕外（手势取消）图标回原位。

### F1.6 壁纸（P0）

- 直接显示系统壁纸（含动态壁纸），本桌面不保存、不读取壁纸文件，不需要存储权限。
- 桌面菜单与设置里的「壁纸」跳系统壁纸选择器。
- 顶部（状态栏后）与底部（底栏后）各有一层很淡的渐变暗化，保证白色文字在亮壁纸上可读。除此之外不遮壁纸。

### F1.7 首次启动与预置图标（P0）

第一次拿到应用列表时，**只做一次**：

| 位置 | 预置内容（设备上解析得到才放；解析不到就空着） |
|---|---|
| 底栏 | 拨号、短信、浏览器、相机 |
| 第 1 页 | 设置、相册、日历、联系人、文件、音乐、计算器、地图、邮件、应用商店（最多 8 个，去重，不与底栏重复） |

- 不预置任何假的图标，不预置助手图标。
- 用户把桌面清空后**不会**再次预置。
- 桌面完全为空时，第 1 页中央显示提示：「桌面还是空的 / 长按空白处，从手机里添加应用」。

### F1.8 Home / 返回键行为（P0）

| 情形 | 行为 |
|---|---|
| 在其他应用里按 Home（本桌面是默认） | 回到桌面，停在上次那一页；抽屉、设置等覆盖页一律关闭 |
| 已经在桌面上再按 Home | 回到第 1 页，关闭所有覆盖页 |
| 抽屉 / 应用管理 / 图标样式 / 设置里按返回 | 回到桌面画布 |
| 底部面板、对话框打开时按返回 | 只关该面板 |
| 桌面画布上按返回（已是默认） | 无反应（桌面不能被「退出」） |
| 桌面画布上按返回（预览模式） | 退出预览，回到之前的界面 |

### F1.9 网格密度（P0）

三档：自动 / 紧凑 / 宽松。这是格子大小，不是手机 / 平板开关。

| 设备 | 档位 | 列 | 行（由屏幕尺寸算出，夹在范围内） |
|---|---|---|---|
| 手机（短边 < 600dp） | 自动 | 4 | (长边 − 220) ÷ 104，取 4–7 |
| | 紧凑 | 5 | (长边 − 220) ÷ 92，取 4–7 |
| | 宽松 | 4 | (长边 − 220) ÷ 124，取 4–7 |
| 平板（短边 ≥ 600dp） | 自动 | 6 | (短边 − 200) ÷ 120，取 3–6 |
| | 紧凑 | 8 | (短边 − 200) ÷ 104，取 3–6 |
| | 宽松 | 5 | (短边 − 200) ÷ 140，取 3–6 |

例：411×891dp 手机「自动」= 4 列 6 行；800×1280dp 平板「自动」= 6 列 5 行。  
切换档位立即重排，规则同 F1.2 的「屏幕尺寸变了」。

## 4. F2 回到系统桌面

「正常桌面」指设备上其他声明了 HOME 的应用（系统自带桌面或用户装的别的桌面）。

### F2.1 临时回到原桌面（P0）

- 直接把那个桌面的主界面调到前台，**不改变默认桌面设置**。
- 之后按 Home 去哪里，仍由系统的默认设置决定：本桌面是默认 → 回本桌面；不是 → 留在那个桌面。
- 入口：桌面菜单「回到系统桌面」；设置 › 主屏幕 ›「回到系统桌面」。

### F2.2 换回默认桌面（P0）

- 第三方应用不能替用户改默认桌面，只能带用户到系统的「默认主屏幕」设置页。
- 入口：设置 › 主屏幕 ›「更换默认桌面」，副标题说明「在系统设置里选回原来的桌面」。

### F2.3 记住常用的那个（P0）

| 设备上别的桌面数量 | 行为 |
|---|---|
| 0 | Toast：「这台设备上没有找到别的桌面」 |
| 1 | 直接切过去 |
| ≥ 2，且之前选过并仍然存在 | 直接切到记住的那个 |
| ≥ 2，没选过或记住的已卸载 | 弹选择框列出全部；选中后切过去并记住 |

设置里显示当前记住的是哪个，并可「重新选择」。

**边界：**

- 过滤掉系统设置应用注册的占位 HOME（仅用于锁屏期间）。
- 个别厂商禁止第三方直接启动其桌面：启动失败时 Toast「打不开那个桌面，可以在系统设置里更换默认桌面」，并提供跳转设置的按钮。此项列入 W0 实测（开发方案 §9）。

**验收：** 本桌面为默认时，切到系统桌面再按 Home 会回到本桌面；预览模式下切过去按 Home 留在系统桌面。

## 5. F3 从手机添加应用

### F3.1 已安装应用目录（P0）

| 项 | 规则 |
|---|---|
| 来源 | 系统 `LauncherApps` 服务报告的、当前用户下所有带启动入口的应用 |
| 粒度 | 一个启动入口（包名 + Activity）一条。同一应用有多个入口时各算一条 |
| 排除 | 本桌面自己 |
| 可见性 | 清单用 `<queries>` 声明「可启动应用」与「其他桌面」两类意图，**不申请** `QUERY_ALL_PACKAGES` |
| 不包含 | 工作资料 / 分身空间里的应用（P2） |
| 排序 | 按名称，中文按拼音序 |
| 诚实原则 | 读取失败时保留上一次的列表，不把失败显示成「没有应用」 |

### F3.2 添加到桌面的四条路径（P0）

| 路径 | 操作 | 落位 |
|---|---|---|
| A 应用管理页 | 行尾「添加」按钮 | 从当前桌面页开始找第一个空格；当前页及之后都满 → 回头找前面的页；全满 → 新增一页 |
| B 应用抽屉 | 长按 → 应用面板 → 打开「放在桌面」 | 同上 |
| C 桌面菜单 | 「添加应用」→ 进应用管理页，筛选预选「未添加」 | 同 A |
| D 助手 | 助手请求「把〈应用〉放到桌面」，可指定页 | 指定页优先，规则同上；需用户确认（F6.3） |

- 已在桌面的应用再添加：不重复放，提示「已经在桌面上」。
- 添加成功 Toast：「『〈名称〉』已放到桌面第 N 页」。
- **不做**「导入原桌面的布局」：系统不向第三方开放别的桌面的布局数据。

### F3.3 安装 / 卸载 / 更新同步（P0）

| 系统事件 | 桌面反应 |
|---|---|
| 安装新应用 | 抽屉与应用管理里立即出现；是否上桌面见 F3.4 |
| 卸载应用 | 桌面页图标、底栏图标、该应用的单独图标样式、隐藏标记一并清除 |
| 应用更新（图标 / 名称变了） | 重新加载该应用的图标与名称 |
| 应用的某个启动入口在更新后消失 | 对应图标清除 |
| 应用被停用 / 移到不可用存储 | 视同暂时不存在，图标清除 |

### F3.4 新装应用自动上桌面（P1）

设置开关「新安装的应用自动放到桌面」，**默认关**。打开后，新装应用按 F3.2-A 的规则落位，并 Toast 提示。首次读取应用列表（预置阶段）不触发。

### F3.5 从抽屉直接拖到桌面（P1）

抽屉里长按并拖动图标：抽屉淡出，进入与 F1.5 相同的拖放流程；没拖动就松手仍打开应用面板。

## 6. F4 应用管理页

一页管全部已安装应用与它们在桌面上的状态。入口：桌面菜单、抽屉右上角「管理」、设置。

### F4.1 列表、搜索、筛选（P0）

| 项 | 规则 |
|---|---|
| 列表项 | 图标（按当前样式）、名称、一行状态、行尾主操作按钮 |
| 状态行 | 由下列片段用「 · 」连接：`桌面第 N 页` / `底栏` / `已隐藏` / `已允许操作桌面`；一个都没有时显示 `未添加` |
| 行尾按钮 | 未在桌面 → 实心「添加」；已在桌面 → 描边「移除」 |
| 点整行 | 打开应用面板（F4.2） |
| 搜索 | 应用名或包名，包含匹配，不区分大小写 |
| 筛选 | 单选：全部 / 桌面上 / 未添加 / 已隐藏；每项后面带数量 |
| 汇总 | 筛选下方一行：「共 N 个应用 · 桌面上 M 个」 |
| 空结果 | 「没有符合条件的应用」 |

### F4.2 单个应用的全部操作：应用面板（P0）

应用面板是一个底部面板，**全产品只有这一个**：桌面图标长按、底栏长按、抽屉长按、应用管理页点行，打开的都是它。

| 区域 | 内容 |
|---|---|
| 头部 | 图标、名称、包名；右侧「打开」 |
| 开关 | 放在桌面（副标题：在第 N 页 / 未添加） |
| 开关 | 钉在底栏（底栏满且未钉时禁用，副标题「底栏已满」） |
| 开关 | 在抽屉中隐藏（副标题：仍可在应用管理里找到） |
| 图标样式 | 该应用单独的外形与风格（见 F5.4） |
| 开关 | 允许它作为助手操作桌面（见 F6.1；副标题说明能做什么） |
| 按钮 | 应用信息（跳系统的应用详情页） |
| 按钮 | 卸载（仅非系统应用显示；交给系统确认弹窗） |

卸载由系统完成并自带确认；本桌面只发起，不绕过。

### F4.3 多选批量操作（P1）

长按列表项进入多选：顶栏变为「已选 N 项」，提供「全选当前筛选」「添加到桌面」「从桌面移除」「隐藏 / 取消隐藏」。批量添加超过 20 个时先弹确认，说明会新增几页。

### F4.4 排序（P1）

按名称（默认）/ 按最近安装。

**验收（F4 整体）：** 四个筛选的数量之间自洽（桌面上 + 未添加 = 全部）；在面板里切任何一个开关，列表状态行立即变化；从四个入口打开的是同一个面板。

## 7. F5 图标样式

图标 = **外形**（裁成什么轮廓）× **风格**（轮廓里画什么）。两者独立选择，共 36 种组合，另加大小、名称、主题色。

### F5.1 外形（P0）

| 外形 | 说明 |
|---|---|
| 圆形 | 正圆 |
| 圆角方 | 圆角为边长 24% 的圆角矩形 |
| 超椭圆（默认） | 指数 4.2 的超椭圆，比圆角矩形更饱满 |
| 水滴 | 三个角全圆、右下角小圆角 |
| 六边形 | 尖朝上的六边形，角做柔化 |
| 花瓣 | 八瓣浅波浪圆 |

### F5.2 风格（P0）

| 风格 | 画法 | 自适应图标（新式） | 旧式图标 |
|---|---|---|---|
| 原生（默认） | 应用自己的图标，只换外形 | 背景层 + 前景层铺满并裁切 | 浅色底板 + 原图缩到 68% 居中 |
| 玻璃 | 半透明白色底板（上深下浅）+ 1dp 白色半透明描边 | 只画前景层 | 原图缩到 68% |
| 单色 | 深色底板（混入 16% 主题色）+ 主题色图形 | 有系统「主题图标」层 → 用它着色；没有 → 整图转灰度再着色 | 原图缩到 68%，转灰度再着色 |
| 渐变 | 由图标自身底色生成的三段斜向渐变底板 | 只画前景层 | 原图缩到 68% |
| 描边 | 极淡的深色底 + 1.5dp 白色描边 | 只画前景层 | 原图缩到 68% |
| 字母 | 按应用固定配色的渐变底板 + 应用名首字（白色、半粗） | 同左 | 同左 |

规则：

- 「字母」的颜色由应用标识算出，同一应用每次颜色相同。
- 「渐变」的底色：自适应图标取其背景层的平均色；旧式图标取主色调并向白色混合成浅色。
- 图标还没加载出来时显示一块同外形的半透明占位，不闪烁、不显示破图。
- 不透明底板的风格（原生、单色、渐变、字母）带轻微投影；玻璃与描边不带。

### F5.3 大小、名称、主题色（P0）

| 项 | 范围 | 默认 |
|---|---|---|
| 图标大小 | 70%–130%，步进 5% | 100% |
| 显示应用名称 | 开 / 关（作用于桌面页与抽屉；底栏始终不显示名称） | 开 |
| 主题色（仅「单色」风格用） | 6 个预设：蓝、绿、琥珀、珊瑚、紫、近白 | 蓝 |

图标基础尺寸 = min(格宽 × 0.62, 格高 × 0.56, 64dp)，不小于 36dp；再乘以大小百分比。

### F5.4 单个应用单独设置（P0）

- 在应用面板的「图标样式」里，可为该应用单独选外形和 / 或风格。
- 只保存与全局不同的那一项；没单独设的那一项继续跟随全局。
- 选项以**该应用自己的图标**做成小预览，所见即所得。
- 再点一次已选中的单独项 = 取消该项；「跟随全局」一键清除该应用的全部单独设置。
- 大小、名称、主题色只有全局设置，没有单应用设置。
- 图标样式页底部显示「有 N 个应用使用单独样式」，可一键全部清除（弹确认）。
- 应用卸载后，其单独设置自动删除。

### F5.5 第三方图标包（P2）

不在本轮。方向：识别 ADW / Nova 格式图标包并作为第七种「风格来源」。

**验收（F5 整体）：** 6 × 6 组合逐一截图，无裁切错位、无破图；改全局后，有单独设置的应用保持其单独项；杀进程重开样式不丢。

## 8. F6 人机协同

### 8.0 模型

```
   用户的手势 ───────────────┐
                              ▼
                      ┌──────────────┐
                      │  桌面控制器   │ ← 唯一能改桌面状态的地方
                      └──────────────┘
                              ▲
   助手的请求 → ①授权 → ②合法性 → ③冲突 → ④确认闸门 → ⑤执行 → ⑥展示给用户
```

- 用户和助手改的是**同一份**桌面状态，没有「助手专用模式」，不锁屏、不抢占。
- 用户的手势直达控制器；助手的每个请求必须依次过 ①–④ 才会执行。
- 助手操作的是桌面**自己的状态**（翻页、抽屉、图标、启动应用），走桌面内部接口，不靠无障碍去「点」桌面。

### F6.1 助手授权（P0）

| 项 | 规则 |
|---|---|
| 默认 | 没有任何应用被允许 |
| 授权方式 | 用户在应用面板里打开「允许它作为助手操作桌面」，或在设置 › 助手与操控里添加 |
| 身份识别 | 以系统报告的**调用方包名**为准，助手无法自报身份 |
| 已知助手提示 | 检测到已安装 DSH Go 时，设置页该区顶部显示一行建议，仍需用户手动打开 |
| 撤销 | 同一开关关闭，立即生效 |
| ADB 调试 | 仅调试版可见的开关「允许 ADB 作为助手」，默认关；正式版无此项且永不生效 |
| 未授权的调用 | 只能得到「协议版本、是否已授权」；其余一律拒绝，不弹任何界面打扰用户 |

授权文案必须写清授权意味着什么：「它可以查看桌面布局和应用列表，并请求翻页、打开应用、整理图标。改动桌面和打开应用前会先问你（可在确认档位里调整）。」

### F6.2 助手可请求的桌面动作（P0）

| 动作 | 说明 | 类别 |
|---|---|---|
| 查看桌面布局 | 页数、当前页、网格、每个图标的应用与位置、底栏、图标样式 | 读取 |
| 查看应用列表 | 可启动应用的名称与包名、是否在桌面 / 底栏。**不含用户隐藏的应用** | 读取 |
| 翻到第 N 页 | | 浏览 |
| 打开 / 关上应用抽屉 | 用户正在设置类页面时拒绝打开 | 浏览 |
| 打开应用 | 以包名指定 | 启动 |
| 把应用放到桌面 | 可指定页 | 改动 |
| 把应用从桌面拿走 | 不卸载 | 改动 |
| 移动图标 | 指定页、列、行；目标有图标则换位 | 改动 |
| 钉到底栏 / 从底栏拿走 | | 改动 |
| 更换图标样式 | 全部图标或单个应用的外形 / 风格 | 改动 |
| 报告状态 | 空闲 / 思考中 / 执行中 / 需要用户，附一句话（≤ 80 字） | 状态 |
| 结束任务 | 助手主动告知本任务结束 | 状态 |

**助手永远不能做的事**（协议里不提供，也不得在后续版本悄悄加）：卸载应用；隐藏 / 取消隐藏应用；改授权名单与确认档位；设为或更换默认桌面；换壁纸；解除停止状态；代替用户点确认卡。

### F6.3 确认档位（P0）

三档，默认最严。只有用户能改；改档后，之前「本任务已确认」的记录清空。

| 动作类别 | 每次都询问（默认） | 本任务免确认 | 始终免确认 |
|---|---|---|---|
| 读取、状态 | 不问 | 不问 | 不问 |
| 浏览（翻页、抽屉） | 不问 | 不问 | 不问 |
| 启动（打开应用） | **每次问** | 每个任务问一次 | 不问 |
| 改动（图标增删移、底栏、样式） | **每次问** | 每个任务问一次 | 不问 |

- 「任务」由助手在请求里带的任务标识区分；不带则归入该助手的默认任务。助手结束任务或用户停止后，该任务的确认作废。
- 选择「始终免确认」前弹二次确认，写明风险。
- 确认卡：标题「〈助手名〉想要」，正文是这次动作的人话描述（如「把『飞书』放到桌面」），按钮「允许这次」「不允许」，另有「停止」。
- 一次只显示一张确认卡，其余请求排队。60 秒无人回应视为超时，按未允许处理。
- 确认卡在本桌面的**任何界面**（画布、抽屉、应用管理、设置……）上都要能看到并作答。
- 桌面不在前台时：读取与状态类请求照常；其余一律拒绝并告知助手「桌面不在前台」。

### F6.4 让用户看得见（P0）

助手做的每件事都要在屏幕上有迹可循。

| 元素 | 何时出现 | 表现 |
|---|---|---|
| 桌宠 | 有至少一个已授权助手（或调试开关已开，或演示脚本运行中）时，出现在桌面画布上 | 可拖到任意位置，位置记住；不占格子。颜色与表情随状态变（见下表）。点一下打开助手面板 |
| 状态条 | 助手报告状态、或刚执行完一个动作时 | 底栏上方的小条：「〈助手名〉：〈一句话〉」+「停止」。动作结果停留 3.5 秒；助手自报的状态最多停留 20 秒 |
| 图标高亮 | 助手打开、添加、移动某应用或改它的图标时 | 该图标外圈出现主题色圆角框约 1.8 秒；必要时桌面自动翻到它所在的页 |
| 确认卡 | 见 F6.3 | |
| 助手面板 | 点桌宠 | 当前状态、停止 / 继续、最近 8 条操作记录（时间、谁、做了什么、结果）、「打开〈助手〉」、「管理助手」 |

| 助手状态 | 桌宠 | 无障碍朗读 |
|---|---|---|
| 空闲 | 蓝灰色，睁眼 | 助手，空闲 |
| 思考中 | 琥珀色，轻微呼吸动画 | 助手，正在思考 |
| 执行中 | 绿色 | 助手，正在操作 |
| 需要用户 | 琥珀色，带「!」 | 助手，需要你确认 |
| 已停止 | 灰色，闭眼 | 助手，已停止 |

操作记录只保留最近 40 条，只在内存里，不落盘；不记录屏幕内容和输入内容。  
桌面不可见或息屏时桌宠动画停止。

### F6.5 停止与恢复（P0）

| 项 | 规则 |
|---|---|
| 停止入口 | 状态条、确认卡、助手面板，三处都有 |
| 停止的效果 | 立即：撤回当前确认卡；排队中的请求全部按「已停止」返回；清空「本任务已确认」记录；桌宠变灰 |
| 停止之后 | 所有助手的所有请求（含读取以外的一切）都被拒，并告知原因 |
| 恢复 | **只能由用户**在助手面板点「继续」。助手无法自行恢复 |
| 息屏 | 息屏时若有助手正在执行或等待确认，自动停止，状态条写「已息屏，助手任务已停止。」 |
| 范围 | 停止是全局的（不分助手）。P1 评估按助手分别停止 |

### F6.6 人机同时操作的冲突规则（P0）

原则：**用户优先，助手让路，结果可预期。**

| 情形 | 规则 |
|---|---|
| 用户正在拖动某个图标，助手请求移动 / 移除同一个图标 | 拒绝，返回「用户正在操作」 |
| 用户正在拖动任意图标，助手请求翻页 | 拒绝，返回「用户正在操作」 |
| 用户正在手动滑动分页，助手请求翻页 | 拒绝，返回「用户正在操作」 |
| 用户在设置 / 应用管理 / 图标样式页，助手请求改动桌面 | 允许（照常过确认）；改动在后台生效；不把用户拽回桌面 |
| 用户在上述页面，助手请求打开抽屉 | 拒绝并说明 |
| 助手等待确认期间，用户自己把那件事做了（如自己把应用加到了桌面） | 用户点「允许」后，执行时发现已是目标状态，回报「已经在桌面上」，不重复操作 |
| 助手等待确认期间，前提不成立了（如应用被卸载、目标页被收掉） | 执行前重新校验，失败则回报原因，不做半截操作 |
| 两个助手同时请求 | 按到达顺序逐个处理；确认卡一次一张 |
| 助手请求过快 | 每个助手每秒最多 5 个改动 / 启动类请求，超出返回「请求过于频繁」；读取类不限 |

每个动作要么完整生效要么不生效，不存在「移了一半」。

### F6.7 撤销助手的改动（P1）

助手完成一次「改动」类动作后，状态条在 5 秒内提供「撤销」。点击后桌面布局与图标样式恢复到该动作之前；若这期间用户自己也改过，撤销按钮不显示（避免把用户的改动一起冲掉）。只支持撤销最近一次。

### F6.8 内置演示脚本（P0）

设置 › 助手与操控 ›「看一次演示」。一段固定脚本以「演示脚本」的名义，走与真实助手**完全相同**的闸门：

1. 报告状态「先看看桌面上有什么」
2. 桌面多于 1 页时：翻到第 2 页，再翻回第 1 页
3. 打开抽屉，再关上
4. 请求把所有图标换成下一种外形（会弹确认卡）
5. 结束任务

入口处必须写明：「这是固定脚本，不是真实助手，不联网。」用户可以在演示过程中随时自己操作或点停止。

### F6.9 样例助手 APK（P1）

仓库内 `sample-agent`：一个独立应用，带一个前台界面和若干按钮，通过协议调用桌面（读取布局、翻页、添加应用、换图标样式）。作用是证明第三方应用能按文档接入，并作为接入示例代码。

### F6.10 在其他应用里点按 / 输入（P2）

需要无障碍服务，属 W0-T4 阻塞项。实测有结论前不写产品代码，界面上也不出现相关入口。

**验收（F6 整体）：**

- 未授权的包调用任何改动接口，桌面无任何界面变化，调用方得到「未授权」。
- 「每次都询问」下，助手请求添加应用必弹确认；点「不允许」后桌面不变，记录里有一条「未允许」。
- 等待确认时点「停止」，确认卡立刻消失，助手收到「已停止」；此后任何请求都被拒，直到点「继续」。
- 助手翻页时用户能同时点开应用，互不卡死。
- 息屏后回来，状态为已停止。

## 10. F8 数据与隐私（P0）

| 项 | 规则 |
|---|---|
| 保存什么 | 桌面布局（页、图标位置、底栏）、图标样式（全局 + 单应用）、设置（密度、隐藏的应用、助手授权与确认档位、记住的系统桌面、桌宠位置、是否已预置） |
| 保存在哪 | 应用私有目录里的一个 JSON 文件。写入先写临时文件再改名，避免写一半被杀 |
| 何时保存 | 任何上述内容变化后约 0.3 秒 |
| 读不出来怎么办 | 把坏文件另存一份（不删），以全新桌面启动 |
| 不保存什么 | 应用列表、图标图片（都从系统现读）、助手操作记录、任何屏幕内容 |
| 网络 | **清单不申请联网权限。** 零上报、零遥测 |
| 系统备份 | 关闭（`allowBackup=false`） |
| 申请的权限 | 仅 `REQUEST_DELETE_PACKAGES`（把卸载请求交给系统确认界面）。不申请存储、无障碍、悬浮窗、全部应用查询 |

## 11. 全局规则

### 11.1 文案

简体中文，短句，带下一步。完整文案表见 [页面设计.md](./页面设计.md) §14；新增界面文案必须先入表再实现。

### 11.2 无障碍（面向系统无障碍用户）

- 图标、底栏按钮、页指示点、桌宠、确认卡按钮都有可朗读的名称。
- 触控目标：图标格子 ≥ 48×48dp；确认卡与停止按钮高度 ≥ 44dp。
- 拖放的替代路径：凡是拖放能做的（放到桌面、钉到底栏、移除），应用面板里都有开关可以完成。

### 11.3 性能指标

| 指标 | 目标 |
|---|---|
| 冷启动到第一帧桌面（网格先出，图标后到） | < 600ms（中端机；W0-T8 回填实测） |
| 从其他应用按 Home 回到桌面 | < 300ms 量级 |
| 分页滑动 | 不掉帧（60fps 设备上 ≥ 55fps） |
| 抽屉打开 200 个应用 | 首屏 < 300ms，滚动不卡 |
| 图标内存 | 单个图标位图边长 ≤ 192px，缓存上限 240 个 |

### 11.4 兼容性

Android 8.0（API 26）– Android 15（API 35）。手机、平板、折叠屏。深色 / 浅色跟随系统；Android 12+ 的设置类页面跟随壁纸取色。
