## 1. 背景与问题

手机 AI 助手（如 DSH Go）已经能聊天、读屏、点按，也有桌宠。但它们仍然生活在「系统默认启动器之上的一层悬浮物」里：

- 主屏幕是别人的，助手只是贴在上面；
- 每家助手各自申请悬浮窗与无障碍，权限和确认是散的；
- 在平板上，也很少有一张真正能摆窗口、让助手和正在做的事共处的桌面。

用户需要的不是再做一个看板 App，而是一张**属于助手的安卓桌面**：按 Home 就回来，助手在上面，也能动手去点这张桌子。

---

## 2. 产品愿景

> 在安卓平板和安卓手机上，提供一套可设为默认主屏幕的原生桌面；DSH Go、DeepDeep 这类助手可以在这张桌面上驻留显示，并在用户授权后操作桌面与其上的应用。

### 2.1 目标用户

- 同时使用一台安卓平板和/或安卓手机，希望主屏幕就是工作桌面，而不是应用列表
- 已经或打算使用 DSH Go 这类本机 AI 助手，希望它出现在桌面上，而不是每次先打开 App
- 能接受侧载安装、并认真处理无障碍与截屏等敏感权限的个人用户

### 2.2 目标设备

| 设备 | 体验目标 |
|---|---|
| 安卓手机 | 启动器形态：分页桌面、底栏、应用抽屉；助手在桌面上驻留 |
| 安卓平板 | 优先桌面窗口形态：任务栏、图标、多窗口；助手与窗口同屏 |

系统基线：**Android 8.0（API 26）** 可安装，与 DSH Go 对齐。自由窗口、Desktop Windowing、部分桌面窗口能力仅在系统/OEM 支持时启用（通常是 Android 12L / 15 / 16 及部分大屏设备），见已知限制。

### 2.3 非目标

见 [重构决策.md](./重构决策.md) §6。此处不重复展开。特别强调：本产品不是 iPad Desk 的安卓版应用。

### 2.4 已知限制（架构决定，不是没做完）

| # | 限制 | 原因 | 缓解 |
|---|---|---|---|
| L1 | 第三方桌面不能替换系统导航栏、通知栏与最近任务的完整实现 | 这是系统权限边界 | 不承诺「整机变成另一套 OS」；只做主屏幕与（在支持时）窗口组织 |
| L2 | 并非所有平板都开放自由窗口 / Desktop Windowing | OEM 与系统开关决定 | W0 实测后给出机型能力表；不支持时降级为启动器形态，并在设置里如实说明 |
| L3 | 未设为默认桌面时，按 Home 不会回到本产品 | 这是 Android 的 HOME 角色机制 | 首次引导明确请求「设为默认主屏幕」；未设置时顶栏标明「预览模式」 |
| L4 | 非协作模式下，助手自己的桌宠/悬浮窗仍由对方控制 | 本桌面不能改第三方 APK | 协作 SDK 落地前，允许并存，并在设置里提示可能出现两只桌宠 |
| L5 | 助手操作屏幕时，内容可能被该助手发给其模型提供方 | 本桌面不代理模型请求 | 权限说明写清「谁在读屏、数据去向由哪款助手决定」；本桌面默认不上传 |

## 3. 功能范围与分期

### 3.1 本仓库现状

核心模型与单测已完成；桌面应用的骨架已写、能编译，但尚未在设备上运行，入口界面未完成，**现在还不能当主屏幕使用**。逐文件状态见 [开发方案.md](./开发方案.md) §1。窗口合成、无障碍注入在 W0 结论前不写。

### 3.1.1 本轮范围（2026-11-12 增补）

在 §3.2 的 MVP 之上，本轮同时纳入：回到系统桌面、应用管理页、多种图标样式，以及**只作用于桌面自身**的人机协同（授权、确认、停止、桌宠、状态条）。后者原属 §3.3 的第 2、3 条，其中不依赖无障碍的部分提前；依赖无障碍的部分仍在 Phase 2。完整清单与优先级见 [功能设计.md](./功能设计.md) §1。

### 3.2 原生 MVP（M1–M3）

必须同时满足「看起来是桌面」和「能被设成桌面」：

1. 可安装的原生应用，声明 `HOME` / `DEFAULT`，能被系统列为默认主屏幕候选项
2. 桌面页：壁纸、应用图标、左右滑分页、对齐网格
3. 手机底栏（常用应用）+ 应用抽屉 + 应用搜索
4. 首次启动引导：预览模式说明，并请求设为默认主屏幕
5. 长按桌面：进入整理模式（移动图标、改壁纸入口）
6. 平板在中等宽度以上改用任务栏，而不是生搬手机底栏

### 3.3 Phase 2（M4–M6）

1. 文件夹、桌面小组件（App Widget Host）、桌面搜索增强
2. 助手舞台：桌宠层、助手面板槽位、样例助手走 SDK
3. 共享桌面操控面：无障碍读屏与手势，带确认档位与一键停止
4. 非协作接入：识别已安装的 DSH Go，放到桌面/任务栏，并在支持时以窗口打开
5. 在 W0 为正向的设备上启用桌面窗口形态（自由窗口 / Desktop Windowing）

### 3.4 之后再评估（不承诺）

- 与 DSH Go 的正式协作适配（需对方实现 SDK 或提供插件）
- DeepDeep 等其他助手的白名单与适配
- 通知角标、深色壁纸智能对比、多用户/工作资料
- 对接 iPad Desk 用量 Host（仅在明确需要时）

## 4. 用户流程

### 4.1 首次使用

1. 侧载安装 APK，打开 Android Desk（此时为预览模式）
2. 看到真实桌面画布（壁纸、默认图标网格），顶栏标明「预览模式，尚未设为默认主屏幕」
3. 引导请求「设为默认主屏幕」；用户在系统选择器中确认
4. 之后按 Home 回到本桌面
5. 助手相关权限（悬浮跟随、无障碍、截屏）**不在这一步强要**，等到用户打开「助手与操控」时再说明并申请

### 4.2 日常（启动器形态）

- 主屏幕滑页、点图标、从抽屉启动应用
- 助手桌宠/面板在桌面上可见；点它开始对话或交代任务
- 打开其他应用后离开桌面；按 Home 回来，布局与助手位置保持

### 4.3 日常（桌面窗口形态）

- 从任务栏或图标打开应用，应用以窗口出现在桌面上
- 助手仍在桌面上，可以指着某个窗口或图标去操作
- 需要用户本人处理的步骤（密码、支付）时，桌面给出「需要你来操作」状态，助手停手

## 5. 需求条目（可验收）

### 5.1 方向验收（本修订必须满足）

- 文档与 README 不得把产品写成「安卓版 iPad Desk」或「全屏看板应用」
- 主路径是默认主屏幕；预览模式有明确文案
- 助手驻留与桌面操控被写成产品能力，而不是可选壁纸主题

### 5.2 MVP 验收

- 在至少一台手机和一台平板（或平板模拟器）上可设为默认主屏幕，按 Home 返回本桌面
- 图标分页、底栏/任务栏、应用抽屉可用
- 未授权助手权限时，桌面本身完整能用
- 预览模式与已设为默认，两种状态文案正确

### 5.3 Phase 2 验收

- 样例助手能在桌面上显示桌宠或面板，并上报至少空闲/执行两种状态
- 共享操控在「每次都询问」档位下，敏感操作会弹出确认，且一键停止立刻生效
- 已安装的 DSH Go 能被识别并放到桌面上（非协作即可过验收）
- 在 W0 标明「支持自由窗口」的设备上，至少一个应用能以窗口开在桌面上；不支持的设备显示降级说明，而不是空白或崩溃

---

## 6. 成功标准

- 评审者会把它叫做「桌面 / 启动器」，而不是「一个 App」
- 设为默认后，按 Home 回到本产品的时间观感与系统启动器相当（目标：从后台恢复 < 300ms 量级，W0 回填实测）
- 不开启任何助手权限时，它仍是一张能日常使用的桌面
- 默认零公网上报
