## 0. 接手须知

### 0.1 阅读顺序

1. [重构决策.md](./重构决策.md)：这是一张**安卓原生桌面（Launcher）**，不是应用，不是 WebView。
2. 本文 §1（代码现状）、§2（硬规则）、§3–§6（架构、模型、接口、协议）。
3. 你领到的工作包（§8）→ 它引用的 [功能设计.md](./功能设计.md) 条目（F 编号）和 [页面设计.md](./页面设计.md) 页面（S 编号）。

### 0.2 一分钟概览

- 单 Activity 的 Compose 应用，声明 `HOME`，可设为默认主屏幕。
- 所有桌面状态由一个 `DeskController` 持有（`StateFlow<DeskUiState>`）。**用户的手势和助手的请求最后都调它的同一批方法**——这就是「人机一起操作」的实现方式。
- 助手是别的应用，通过一个 ContentProvider 的 `call()` 进来，经过授权 → 校验 → 冲突 → 确认闸门，才执行。
- 布局、图标样式、设置存成应用私有目录里的一个 JSON 文件。不联网。

## 2. 硬规则（违反即返工）

1. **原生。** 桌面本体用 Kotlin + Jetpack Compose。禁止 WebView。
2. **`core` 不引用 Android。** 布局算法、确认闸门、协议解析必须能在 JVM 上单测。
3. **状态只有一份。** 只有 `DeskController` 能改桌面状态。界面不得另存一份会打架的布局；助手请求不得绕过 `AgentHub` 直接调 `DeskController`。
4. **位置存格子，不存像素。**
5. **不伪造状态。** 不是默认桌面就不说是；应用列表没读到就不说「没有应用」；没做的能力不出现在界面上。
6. **不联网，不加权限。** 清单里不得出现 `INTERNET`、`QUERY_ALL_PACKAGES`、无障碍、悬浮窗。
7. **只有用户能改授权、确认档位、停止状态。** 协议里不得出现能改这三样的方法。
8. **W0 阻塞项不碰。** 自由窗口（T2）、虚拟屏（T3）、无障碍注入（T4）没有实测结论前，不写产品代码，界面上不出现入口。本轮的助手动作只作用于桌面自身，不受此限制。
9. **确认闸门只有一份**，在 `host`（WP8 之后）。`sdk` 与助手改不了档位。
10. **不在日志里写屏幕内容与用户输入。**

## 3. 架构

### 3.1 模块依赖

```
            ┌──────────────────────────────────────────┐
            │ app（Android：Activity、Compose、系统 API） │
            └───┬───────────┬───────────┬─────────┬────┘
                ▼           ▼           ▼         ▼
             client        host ──────► sdk      core
                │            │                    ▲
                └────────────┴────────────────────┘

  sample-agent（独立 APK）──► sdk         箭头 = 「依赖」
```

`core` 与 `sdk` 互不依赖。`sdk` 是对第三方的稳定面，改名或删除常量要升 `DeskProtocol.VERSION`。

### 3.2 运行时结构

```
 LauncherActivity ──setContent──► DeskRoot（Compose）
        │  实现 DeskHost                │ collectAsStateWithLifecycle
        │                               ▼
        │                    ┌─────────────────────┐   读写    ┌───────────┐
        └──生命周期事件────► │   DeskController     │ ────────► │ DeskStore │ desk.json
                             │ StateFlow<DeskUiState>│           └───────────┘
   AgentProvider.call()      │                     │ ◄──列表── AppCatalog（LauncherApps）
        │ binder 线程        │                     │ ◄──图标── IconLoader（缓存）
        ▼                    └──────────▲──────────┘
   ┌──────────┐  prepare()/run()        │
   │ AgentHub │ ────────────────────────┘
   │ StateFlow<AgentUiState>            SystemHome（HOME 角色、其他桌面）
   └──────────┘
```

- `DeskGraph.controller(context)` 是进程内单例。ContentProvider 比 Activity 先创建，所以用懒加载单例而不是放在 Activity 里。
- 桌面壳与宿主同进程（[架构.md](./架构.md) §2）。

### 3.3 线程模型

| 线程 | 做什么 |
|---|---|
| 主线程 | 所有 `DeskController` 的改动方法、Compose、`prepare()` 与 `Prepared.Ready.run()` |
| `Dispatchers.Default` | 查询应用列表、渲染图标位图 |
| `Dispatchers.IO` | 读写 `desk.json` |
| binder 线程 | `AgentProvider.call()`。等待用户确认时**阻塞在这里**（最长 60 秒）。需要碰状态时切到主线程执行 |

`MutableStateFlow.update {}` 的 lambda 可能被重复执行：里面只做纯计算，不做启动 Activity、弹 Toast 之类的副作用。

### 3.4 两条数据流

**用户手势：**

```
触摸 → Compose 手势 → controller.xxx() → _state.update → 界面重组
                                            └─（0.3 秒去抖）→ DeskStore.save
```

**助手请求：**

```
其他应用 ContentResolver.call(authority, method, arg, extras)
  → AgentProvider.call（binder 线程，取 callingPackage）
  → AgentHub.handle
       ① 授权：AgentAccess.isAllowed(调用方包名)            否 → not_allowed
       ② 解析：AgentCommandParser.parse                      错 → invalid
       ③ 停止 / 前台 / 限流 / 用户正忙                       → stopped / desk_not_visible / rate_limited / busy
       ④ 主线程 controller.prepare(command)                  不成立 → invalid（附原因）
       ⑤ ConfirmGate.decide(任务, 动作种类)
            Allow → 继续
            AskUser → 发布 PendingConfirm，阻塞等用户（允许 / 不允许 / 停止 / 超时）
       ⑥ 主线程 prepared.run() → 调 controller 的方法（与用户手势同一批）
       ⑦ 记录、更新桌宠与状态条、高亮
  → 返回 Bundle{status, message, data}
```

## 4. 数据模型

全部在 `core`，都标注了 `@Serializable`。

### 4.1 布局

| 类型 | 字段 | 说明 |
|---|---|---|
| `CellPosition` | `pageIndex` `cellX` `cellY` `spanX=1` `spanY=1` | 0 起；构造时校验非负与跨度 ≥ 1 |
| `DeskItem` | `id` `kind`(App/Folder/Widget) `position` `packageName?` `label?` `childIds` `activityName?` | 应用图标的 id = `"app:" + appKey` |
| `DockSlot` | `index` `itemId?` `packageName?` `activityName?` | `itemId == null` 即空槽；从应用列表直接钉入的 id = `"dock:" + appKey` |
| `GridSpec` | `columns` `rows` `dockSlots` | |
| `DesktopLayout` | `grid` `items` `dock` `pageCount` | 不可变；所有操作返回新对象 |

`appKey(包名, Activity)` = `"包名/Activity类名"`（Activity 为空时就是包名）。它是图标样式覆盖、隐藏标记、图标缓存的统一键。

`DesktopLayout` 的操作（全部已实现并测试）：

| 方法 | 行为 |
|---|---|
| `placeApp(pkg, activity, label, preferredPage)` | 找空位规则见 F3.2；已存在则原样返回 |
| `removeApp(pkg, activity)` | 只移桌面页图标，不动底栏 |
| `removeItem(id)` | 按 id 移除，并清掉引用它的底栏槽 |
| `moveItem(id, to)` | 空位则移，同尺寸占用则换位，否则原样返回 |
| `pinAppToDock(pkg, activity, slot?)` / `unpinAppFromDock` | |
| `retainApps(isPresent)` / `removeUninstalled(packages)` | 清理不存在的应用（图标 + 底栏） |
| `withGrid(newGrid)` | 换网格重排，规则见 F1.2 |
| `addPage()` / `trimTrailingEmptyPages()` | |
| `firstFreeCell(page)` / `firstFreeCellFrom(startPage)` | |

### 4.4 持久化

- 文件：`<应用私有目录>/files/desk.json`；临时文件 `desk.json.tmp`；读坏时的留底 `desk.json.bad`。
- 编解码：`DeskSnapshotCodec`（`ignoreUnknownKeys=true`、`encodeDefaults=true`）。解码失败（含违反模型约束）返回 null。
- **加字段**：给默认值即可，旧文件能读，不必升版本。
- **改语义或删字段**：升 `DeskSnapshot.CURRENT_VERSION`，并在 `DeskSnapshotCodec.decode` 里按 `version` 做迁移，同时补迁移单测。

       "packageName": "com.android.settings", "label": "设置",
       "activityName": "com.android.settings.Settings"}
    ],
    "dock": [{"index": 0, "itemId": "dock:com.android.dialer/...", "packageName": "com.android.dialer", "activityName": "..."},
             {"index": 1, "itemId": null}],

### 5.3 助手请求管线（WP8 目标形态）

把判定逻辑从 `app/agent/AgentHub.kt` 抽到 `host/AgentGatekeeper.kt`，做成纯 Kotlin、可单测：

```kotlin
// host
class AgentGatekeeper(
    private val now: () -> Long,
    private val limits: RateLimit = RateLimit(perSecond = 5),
) {
    sealed interface Verdict {
        data class Reject(val status: String, val message: String) : Verdict
        data class Ask(val taskKey: String, val command: DeskCommand) : Verdict   // 需要问用户
        data class Proceed(val taskKey: String, val command: DeskCommand) : Verdict
    }

    fun check(
        caller: String?, method: String, arg: String?, args: Map<String, String>,
        access: AgentAccess, debuggable: Boolean,
        stopped: Boolean, deskVisible: Boolean, userBusy: UserBusy,
    ): Verdict

    fun confirmed(taskKey: String)      // 用户点了允许
    fun endTask(taskKey: String)
    fun reset()                         // 用户停止、或档位改变
}

// core
data class UserBusy(val draggingItemId: String? = null, val swipingPages: Boolean = false)
```

`AgentHub`（`app`）只剩：调 `check`；`Ask` 时发布确认卡并阻塞等待；主线程执行；更新 `AgentUiState`；记录。  
`UserBusy` 由 `DesktopCanvas` 在拖放开始 / 结束、分页滚动开始 / 结束时报告给 `DeskController`（新增 `setUserBusy(...)`，**不放进 `DeskUiState`**，避免每次拖动都触发全局重组；用单独的 `@Volatile` 字段或独立的 `StateFlow`）。

冲突判定（F6.6）落在 `check` 里：

| `UserBusy` | 命令 | 结果 |
|---|---|---|
| `draggingItemId != null` | `GoToPage` | `busy` |
| `draggingItemId == X` | 针对 X 的 `MoveItem` / `RemoveFromDesktop` | `busy`（需在 `prepare` 之后比对 item id，可放在 `AgentHub` 调 `prepare` 之后做） |
| `swipingPages` | `GoToPage` | `busy` |

限流：按调用方包名的滑动窗口，1 秒内超过 5 个「启动 / 改动」类请求返回 `rate_limited`；读取与状态类不计。

## 6. 助手协议 v1

### 6.1 调用方式

```kotlin
val reply: Bundle? = context.contentResolver.call(
    Uri.parse("content://com.skydream.androiddesk.agent"),
    method,      // 见 6.2
    arg,         // 主参数的简写，可为 null
    extras,      // 其余参数，可为 null
)
```

- 在后台线程调用：等待用户确认时会阻塞，最长 60 秒。
- Android 11+ 的调用方需在自己的清单里声明可见性，否则找不到这个 Provider：

```xml
<queries>
    <package android:name="com.skydream.androiddesk" />
</queries>
```

- 页码、列、行都是 **0 起**。
- 常量定义在 `sdk` 模块的 `DeskProtocol`，接入方应依赖它而不是手写字符串。

### 6.2 方法

| 方法 | `arg`（主参数） | `extras` | 动作种类 | 说明 |
|---|---|---|---|---|
| `hello` | — | — | — | 任何应用可调。`data` = `{"version":1,"allowed":bool,"deskVisible":bool}` |
| `readDesktop` | — | — | 读取 | `data` 见 6.5 |
| `listApps` | — | — | 读取 | `data` 见 6.5 |
| `goToPage` | 页码 | 或 `page` | 浏览 | |
| `openDrawer` / `closeDrawer` | — | — | 浏览 | |
| `launchApp` | 包名 | 或 `package` | 启动 | |
| `addToDesktop` | 包名 | `page`（可选） | 改动 | |
| `removeFromDesktop` | 包名 | | 改动 | 不卸载 |
| `moveItem` | 包名 | `page` `x` `y`（必填） | 改动 | |
| `pinToDock` / `unpinFromDock` | 包名 | | 改动 | |
| `setIconStyle` | 包名（可选；不给 = 全部图标） | `shape` 和 / 或 `treatment`（枚举名，不分大小写） | 改动 | |

### 6.3 返回

Bundle 里固定有 `status`、`message`；读取类另有 `data`（JSON 文本）。

| `status` | 含义 | 助手应该 |
|---|---|---|
| `ok` | 已完成（或已是目标状态） | 继续 |
| `not_allowed` | 用户没有允许这个应用 | 请用户去桌面设置里打开，不要重试 |
| `denied` | 问了用户，用户说不 | 不要立刻重试同一动作 |
| `needs_user` | 这一步桌面不替助手做 | 交还用户 |
| `stopped` | 用户按了停止 | 停下，等用户恢复 |
| `desk_not_visible` | 桌面不在前台 | 等桌面回到前台 |
| `timeout` | 60 秒内没人回应确认 | 可稍后再问一次 |
| `busy` | 用户正在操作同一对象或正在翻页（WP8） | 稍等 1–2 秒重试 |
| `rate_limited` | 请求过快（WP8） | 降低频率 |
| `invalid` | 方法不存在、缺参数、应用不存在、位置放不下等；`message` 说明原因 | 修正请求 |

### 6.4 `message` 文案（会被助手转述给用户，所以写人话）

| 情形 | 文案 |

| 应用不存在 | 没有找到应用：〈包名〉 |
| 页不存在 | 没有第 〈N〉 页，桌面一共 〈M〉 页 |
| 位置越界 | 位置超出桌面：共 〈M〉 页，每页 〈C〉 列 〈R〉 行 |
| 不在桌面 | 「〈名称〉」不在桌面上，先用 addToDesktop 放上来 |

## 7. 实现要点与已知的坑

这些是写基线时已经想清楚、但**还没在设备上验证**的点。接手后请按此实现，并在实机上确认。

### 7.1 成为桌面

| 点 | 做法 |
|---|---|
| 清单 | Activity：`launchMode=singleTask` `clearTaskOnLaunch` `stateNotNeeded` `excludeFromRecents` `resumeWhilePausing` `taskAffinity=""`；自己处理 `orientation|screenSize|screenLayout|smallestScreenSize|keyboard|keyboardHidden|navigation` |
| 是否默认 | Android 10+：`RoleManager.isRoleHeld(ROLE_HOME)`；否则解析 HOME Intent。已封装在 `SystemHome.isDefaultHome()` |
| 请求成为默认 | `SystemHome.roleRequestIntent()` 非 null 时用 `registerForActivityResult(StartActivityForResult)` 发起；为 null 时跳 `Settings.ACTION_HOME_SETTINGS` |
| 结果判断 | **不看 resultCode**，回调里重新调 `refreshHomeRole()`，仍非默认就弹「还没有改过来…」 |
| Home 键 | `onNewIntent` 收到 `ACTION_MAIN + CATEGORY_HOME`：`alreadyOnDesk = hasWindowFocus() && (intent.flags and FLAG_ACTIVITY_BROUGHT_TO_FRONT) == 0`，调 `controller.onHomePressed(alreadyOnDesk)` |
| 返回键 | 根部 `BackHandler(enabled = screen != Desktop \|\| isDefaultHome) { controller.back() }`：默认桌面在画布上吞掉返回；预览模式放行让 Activity 结束 |
| 壁纸 | 主题继承 `Theme.Material.Wallpaper.NoTitleBar`，窗口背景透明。S1、S2 的根容器不得画不透明背景 |
| 全面屏 | `enableEdgeToEdge(SystemBarStyle.dark(TRANSPARENT), SystemBarStyle.dark(TRANSPARENT))`；全屏页在浅色主题下经 `DeskHost.setLightSystemBars(true)` 切深色图标 |
| 方向 | `onCreate` 里：`smallestScreenWidthDp < 600` 则 `requestedOrientation = SCREEN_ORIENTATION_PORTRAIT` |
| 屏幕尺寸 | `onCreate` 与 `onConfigurationChanged` 里取 `configuration.screenWidthDp/HeightDp`，短边、长边传给 `controller.onScreenMetrics` |
| 可见性 | `onStart` 设 `agent.deskVisible = true`，`onStop` 设 false |
| 息屏 | `onCreate` 用 `ContextCompat.registerReceiver(..., RECEIVER_NOT_EXPORTED)` 注册 `ACTION_SCREEN_OFF` → `agent.onScreenOff()`；`onDestroy` 注销 |

### 7.2 应用列表与启动

| 点 | 做法 |
|---|---|
| 来源 | `LauncherApps.getActivityList(null, Process.myUserHandle())`；变化监听 `LauncherApps.Callback` |
| 可见性 | 清单 `<queries>` 两条 Intent（MAIN+LAUNCHER、MAIN+HOME）。一个包只要经任一条可见，对它的其他查询也都可见，所以预置图标时解析拨号、短信等 Intent 不需要额外声明 |
| 启动 | `LauncherApps.startMainActivity(component, user, sourceBounds, null)`，不要自己拼 Intent |
| 卸载 | `Intent(ACTION_DELETE, Uri.parse("package:$pkg"))`，需要 `REQUEST_DELETE_PACKAGES`（已声明） |
| 所有 `startActivity` | 包 `try/catch`，失败给 Toast，不崩 |
| 后台启动限制 | 助手请求打开应用只在桌面前台时受理（`desk_not_visible`），既是产品规则，也避开系统的后台启动 Activity 限制 |

### 7.3 图标渲染

| 点 | 做法 |
|---|---|
| 自适应图标分层 | 每层 108 单位宽、只显示中间 72。画到边长 S 的位图时，把层的 bounds 设为 `(-S/4, -S/4, S+S/4, S+S/4)`。已在 `IconLoader.layers()` |
| 位图尺寸 | `64dp × 屏幕密度`，夹在 96–192px |
| 产物 | `AppIconArt(full, foreground?, monochrome?, adaptive, plate, glyphLuminance)`；`monochrome` 仅 Android 13+ |
| 取色 | `plate`：自适应图标取背景层平均色，旧式图标取按饱和度加权的主色向白混合；`glyphLuminance` 用于校正图形与底板的对比 |
| 缓存 | `LruCache` 240 项；包变化时 `invalidate(pkg)` 并递增 `generation`，界面据此重载 |
| 外形 | `IconShapes.kt` 用 `GenericShape` 画路径。非凸路径（花瓣）在旧系统上可能没有投影，可接受 |
| 别人 APK 的坏资源 | `IconLoader.load` 整体 `try/catch`，失败显示占位，不崩 |

### 7.4 手势（最容易出错的地方）

| 点 | 做法 | 原因 |
|---|---|---|
| 图标上「点按 + 长按拖动」的修饰符顺序 | **`.clickable {}` 在前，`.pointerInput { detectDragGesturesAfterLongPress }` 在后** | 同一节点上靠后的修饰符先收到事件。拖动检测器在后，才能先消费抬手事件，避免「长按后松手」同时触发一次点击 |
| 拖动坐标 | 用 `LayoutCoordinates.localToRoot(change.position)` 换成根坐标，不要累加 `dragAmount` | 跨页时分页在滚动，节点自己在移动，局部增量会包含滚动位移 |
| 跨页拖动 | `HorizontalPager(beyondViewportPageCount = pageCount)` | 被拖图标所在页必须保持在组合里，手势才不会断 |
| 拖动时禁用分页滑动 | `userScrollEnabled = !drag.active` | |
| 空白长按 | 页容器 `detectTapGestures(onLongPress)`；图标的 `clickable` 会消费按下事件，所以长按图标不会同时触发空白长按 | |
| 上滑开抽屉 | 画布根容器 `detectVerticalDragGestures`，累计位移 < −56dp 时打开 | 分页只消费横向，纵向留给它 |
| 分页与控制器同步 | 控制器 → 分页：`LaunchedEffect(currentPage, pageCount) { if (pagerState.targetPage != target) animateScrollToPage(target) }`；分页 → 控制器：`snapshotFlow { pagerState.settledPage }` | 用 `targetPage` 比较，避免用户滑动中被拉回 |
| 系统返回手势 | 屏幕左右边缘归系统。实测（W0-T1）若横滑冲突，在 `Desktop.kt` 里给分页加 `systemGestureExclusion` 或保留纯点指示点的降级 | |

### 7.5 助手入口

| 点 | 做法 |
|---|---|
| 身份 | `ContentProvider.getCallingPackage()`；ADB 的包名是 `com.android.shell` |
| 阻塞等待 | `CompletableFuture<Answer>.get(60s)` 在 binder 线程；**主线程上绝不等待** |
| 切主线程 | `runBlocking(Dispatchers.Main.immediate) { ... }` |
| 一次一张确认卡 | 确认段落用同一把锁串行化 |
| 执行前复查 | 拿到用户允许后、执行前再查一次「是否已停止」；`Prepared.Ready.run()` 内部用最新状态判断（例如已在桌面就不重复放） |
| 演示脚本 | 在独立线程里调同一个 `dispatch`，以固定的调用方标识和显示名「演示脚本」，**不走授权名单但照常过闸门** |

### 7.6 Compose 注意

- `ModalBottomSheet`、`combinedClickable`、`HorizontalPager` 的部分参数在本版本仍需 `@OptIn`。
- 只用 `material-icons-core`（体积小）。需要的图标不在 core 里就用 `Canvas` 画或加矢量资源，不引 `material-icons-extended`。
- 全屏页用 `Scaffold`，注意在 edge-to-edge 下用它提供的内边距。
- 图标列表（抽屉、应用管理）用 `LazyVerticalGrid` / `LazyColumn`，`key = entry.key`。

## 12. 提交与协作约定

- 分支：每个工作包一个分支，名为 `wp<编号>-<简述>`，如 `wp3-app-drawer`。
- 提交说明用中文，首行写做了什么；正文写**在什么设备上验证了哪些验收项**，以及没验证的部分。
