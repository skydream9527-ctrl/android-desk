## 0. 方向纠正（必读 · 不可软化）

本项目**不是**把 [iPad Desk](https://github.com/skydream9527-ctrl/ipad-desk) 搬到安卓上的「一块全屏看板 App」。两者只共享「让 AI 助手出现在一块常亮桌面上」这个意图，产品形态完全不同。

| 错误理解（已废弃） | 正确产品方向 |
|---|---|
| 做一个安卓版 iPad Desk：全屏应用，左右滑看板，经局域网投射 Mac 上的 AI 窗口 | **做一个安卓原生桌面**：作为设备的主屏幕（Launcher / HOME）运行 |
| 用户从应用抽屉里点开「Android Desk」，用完退回系统桌面 | 用户把本产品设为**默认主屏幕**；按 Home / 上滑回桌面，回到的就是它 |
| 助手是另一个 App 里的聊天页，桌面只负责展示卡片或投屏 | 助手（如 DSH Go、DeepDeep）**驻留在这张桌面上**显示，并**操作这张桌面**与其上的应用去互动 |
| WebView / PWA /「添加到主屏幕」网页当作桌面 | **原生 Android 桌面**（Kotlin + Jetpack Compose）；不以 Web 冒充桌面 |

**一句话：** 这是系统主屏幕级别的安卓原生桌面，不是桌面风格的应用。

与 iPad Desk 的关系写清即可，不再沿用它的双端、Mac Host、LAN 窗口流、Cast 作为本产品的主架构。若未来要对接 iPad Desk 的用量 Host，须另开需求，不进入本方案默认范围。

## 1. 产品一句话

一套运行在安卓平板和安卓手机上的**原生桌面**：接管主屏幕，提供壁纸、图标、分页、底栏/任务栏与应用抽屉；并让 DSH Go、DeepDeep 这类手机 AI 助手能在桌面上存在、显示，以及操作桌面去完成互动。

| 角色 | 一句话职责 |
|---|---|
| 桌面本体（Launcher） | 作为 `HOME` 运行：桌面页、图标、小组件、底栏/任务栏、应用抽屉、搜索 |
| 助手舞台 | 把已安装的手机 AI 助手放到桌面上：桌宠、面板、桌面窗口 |
| 桌面操控面 | 在用户授权后，让助手读取与操作这张桌面及桌面上的应用（点按、输入、开应用、摆窗口） |
| 样例助手 | 仓库内的 sample-agent，用来验证宿主协议，不冒充真实第三方产品 |

---

## 2. 为什么必须是「桌面」而不是「应用」

DSH Go 这类助手今天已经能在系统桌面上方用悬浮窗/桌宠出现，也能用无障碍操作手机。它们缺的不是又一个聊天壳，而是一张**把助手当作一等公民的桌面**：

1. **驻留的位置是主屏幕，不是某次打开的 Activity。** 按 Home 回来，助手还在原处，不必先打开某个 App。
2. **桌面本身可被操作。** 助手点的是这张桌面上的图标、文件夹、窗口和底栏，而不是在别人的启动器上「隔空点」。
3. **平板可以走向真桌面。** 在支持自由窗口 / Desktop Windowing 的设备上，应用以窗口形式开在桌面上，助手与窗口共处同一平面；这是应用做不到的。
4. **减少叠罗汉。** 若本产品只是又一个全屏 App，助手仍要各自抢悬浮窗与无障碍；由桌面统一提供舞台和操控面，权限与确认才能收口。

## 3. 原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | 桌面是产品本体 | 主路径是「设为默认主屏幕」。可附带预览模式（未设为 HOME 时以普通 Activity 打开），但预览不是产品形态，不得写成已是桌面 |
| P2 | 原生优先 | Kotlin + Jetpack Compose 实现桌面壳；禁止用 WebView 做桌面本体 |
| P3 | 助手是一等公民 | 桌宠、助手面板、助手窗口与图标、小组件同一层级设计，而不是事后贴一张悬浮窗 |
| P4 | 先本机、后协作 | MVP 即使第三方尚未接入 SDK，也能把已安装助手放到桌面上打开；深度驻留与共享操控走正式 SDK |
| P5 | 权限最小、确认在前 | 读屏、点按、输入必须用户明确开启；发送、支付、删除等敏感操作默认先问；密码、验证码、系统设置默认交还用户 |
| P6 | 诚实分期 | 未实现的能力不进桌面、不写「已可用」。设备不支持自由窗口时，必须说清降级，不得假装已是多窗口桌面 |
| P7 | 本机优先 | 桌面与助手发现、图标、布局均在本机完成；默认零公网上报、零遥测。助手自己把内容发给其模型提供方，由该助手负责说明，本桌面不代为上传 |

## 4. 两种运行形态（必须同时设计，不可只做一种）

| 形态 | 何时出现 | 桌面语义 |
|---|---|---|
| **启动器形态** | 手机，或设备没有可用的自由窗口 / Desktop Windowing | 经典主屏幕：壁纸、图标分页、底栏、应用抽屉。打开应用后离开桌面；按 Home 返回。助手在桌面上驻留；离开桌面后，桌宠是否跟到其他应用上方，由设置显式开关（默认关） |
| **桌面窗口形态** | 平板，或 Android 15/16 及 OEM 已开启 Desktop Windowing / freeform 的设备 | 应用在桌面上以可移动、可缩放的窗口打开；任务栏常驻；助手与窗口同屏。这是平板体验的目标形态 |

两种形态共用同一套桌面数据（图标布局、分页、助手绑定）。能否进入桌面窗口形态，以 W0 实测为准，不得假设所有安卓平板都已开放自由窗口。

## 5. 与第三方助手的关系

本桌面**不重新实现** DSH Go 或 DeepDeep 的引擎、模型配置或对话。本产品提供桌面与宿主协议；助手继续是独立安装的应用。

| 接入深度 | 需要对方改动 | 桌面上能做什么 |
|---|---|---|
| **非协作（MVP 可做）** | 否 | 把已安装助手放上桌面图标/底栏；在桌面窗口形态下把该应用作为窗口打开；用户在桌面上启动它 |
| **协作（Phase 2）** | 是，实现本仓库 Agent SDK | 桌宠与面板由桌面宿主摆放；状态（空闲/思考/执行/等待确认）由助手上报；桌面操控走统一确认闸门，避免再抢一套无障碍 |

首个明确的对标与接入目标是 [DSH Go](https://github.com/ccch1mneyyy/dsh-Go)（DeepSeek Harness 的安卓客户端，已有桌宠与手机操控）。DeepDeep 按同一类「可驻留、可操作设备的手机 AI 助手」预留白名单与 SDK 槽位；其包名、是否可协作，列为开放问题，不写成已对接。

## 6. 明确不做

- 做成 iPad Desk 的安卓客户端，或依赖 Mac Host / 局域网窗口流才能工作
- 用 WebView / PWA 冒充桌面
- 定制 ROM、改 SystemUI、替换系统导航栏或最近任务（第三方桌面做不到的，不承诺）
- 在本产品内嵌各家助手的官方网页，当作助手本体
- 成为通用启动器市场的「再造一个 Lawnchair / Pixel Launcher」（可以借鉴交互，但产品中心是助手驻留与桌面操控）
- 默认在未设为 HOME 时宣称「已经是系统桌面」
- 公有云 SaaS、多用户账号、跨公网远程桌面作为产品承诺
- 绕过用户确认去完成支付、发送、删除，或代填密码与验证码（除非用户在设置里显式解除，且每次解除都再确认）

## 7. 工程与仓库边界

- 产品代码在 `AndroidDesk/`，方案在 `方案/`。
- 共享逻辑（页模型、助手绑定、确认闸门、布局数据）放纯 Kotlin 模块，可在无 Android SDK 时单测。
- 真正的窗口合成、无障碍注入、设为默认桌面，等 [待实测清单.md](./待实测清单.md) 的阻塞项有结论后再填实现，避免先写出要推翻的代码。

## 9. 增补（2026-11-12）：本轮范围

项目负责人追加五条产品要求。它们都落在 §1 的角色表之内，不改变产品形态；这里只记录纳入范围的决定与两处需要说清的边界。

| # | 要求 | 落在哪个角色 | 展开 |
|---|---|---|---|
| R1 | 实现安卓的桌面 | 桌面本体 | 功能设计 F1 |
| R2 | 用户和 AI 助手可以一起操作 | 桌面操控面 | 功能设计 F6 |
| R3 | 可以切换回正常桌面 | 桌面本体 | 功能设计 F2 |
| R4 | 桌面上的应用从手机里添加，有应用管理页 | 桌面本体 | 功能设计 F3、F4 |
| R5 | 应用图标样式多样 | 桌面本体 | 功能设计 F5 |

**边界一：图标样式与应用管理不等于「再造一个通用启动器」。** §6 的那条不做项仍然有效。这两项是「能日常当桌面用」的基本面，做到够用为止；产品中心仍是助手驻留与桌面操控。第三方图标包、主题商店之类不在范围内。

**边界二：本轮的「一起操作」只作用于这张桌面自身。** 翻页、开关抽屉、增删移动图标、换图标样式、打开应用，走的是桌面自己的状态机，不经无障碍，因此不受 [待实测清单.md](./待实测清单.md) 阻塞项的限制，可以现在做。助手在**其他应用里**点按与输入仍属 W0-T4，结论出来前不写、不露出入口。

**协议形态的选择：** [助手宿主架构.md](./助手宿主架构.md) §7 写的是「绑定服务 + AIDL（或等价的官方 IPC）」。本轮 v1 采用 ContentProvider 的 `call()`：它同样是官方 IPC，能由系统给出调用方包名（授权依据），且一次调用一个动作、可阻塞等待用户确认，足够承载桌面自身的动作。由桌面渲染的桌宠内容、面板卡片等需要长连接的能力，仍按原计划在 M4 用绑定服务实现。
